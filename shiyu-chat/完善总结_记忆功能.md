## 核心功能

### 1. 记忆类型

#### 短期记忆
- **作用**: 维持当前会话的上下文连贯性
- **内容**: 最近的对话内容（用户问题和 AI 回答）
- **容量**: 每个会话最多 10 条
- **过期**: 24 小时后自动过期

#### 长期记忆
- **作用**: 存储用户的重要信息和偏好
- **内容**: 从对话中提取的关键信息
- **容量**: 每个用户最多 50 条
- **过期**: 永久保存
- **提取**: AI 自动分析和评分

### 2. 工作流程

```
用户请求
   ↓
MEMORY_LOAD (加载记忆)
   ↓
INTENT (意图识别)
   ↓
CHAIN_EXECUTE (执行子链: Direct/CoT/ToT)
   ↓
MEMORY_SAVE (保存记忆)
   ↓
AI 回复
```

### 3. API 使用示例

#### 第一轮对话
```bash
POST http://localhost:9001/chat
{
  "text": "你好，我叫张三，是一名软件工程师",
  "userId": "user_zhangsan"
}

# 响应包含 sessionId
{
  "result": "你好，张三！",
  "sessionId": "abc123"
}
```

#### 第二轮对话（使用 sessionId）
```bash
POST http://localhost:9001/chat
{
  "text": "你还记得我是做什么的吗？",
  "sessionId": "abc123",
  "userId": "user_zhangsan"
}

# AI 会回答：你是一名软件工程师
```

## 技术亮点

### 1. 基于 LiteFlow 的编排
- 将记忆加载和保存作为独立节点
- 与现有意图识别、对话模式无缝集成
- 流程清晰，易于扩展和维护

### 2. 自动记忆提取
- 使用 AI 自动分析对话内容
- 提取重要信息存储为长期记忆
- 基于规则评分，优先保留关键信息

### 3. 上下文感知
- 所有对话模式（Direct/CoT/ToT）自动使用记忆
- 在 Prompt 中动态添加相关记忆和历史
- 保持对话的连贯性和一致性

### 4. 灵活的存储架构
- 当前基于内存实现（ConcurrentHashMap）
- 易于扩展到数据库或 Redis
- 支持向量检索等高级特性

## 性能考虑

### 内存占用
- 短期记忆：每会话 ~10 条记录
- 长期记忆：每用户 ~50 条记录
- 对话历史：每会话 ~5 条记录
- 建议：生产环境使用 Redis 等外部存储

### 响应时间
- 记忆加载：< 1ms（内存读取）
- 记忆保存：< 5ms（含 AI 提取）
- 对整体响应时间影响较小

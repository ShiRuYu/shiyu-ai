# 对话功能说明

## 架构概述

本对话系统基于 **LiteFlow** 流程编排引擎，实现了三种不同的对话模式：

### 1. **Direct（直接对话）** 
- 适用于简单的问答、寒暄场景
- 直接调用大模型返回答案
- 快速响应，无额外处理

### 2. **CoT（Chain of Thought - 思维链）**
- 适用于逻辑推理、数学问题等需要逐步推导的场景
- 引导模型按照"理解问题 → 分析条件 → 逐步推导 → 得出结论"的流程思考
- 提供更严谨、结构化的回答

### 3. **ToT（Tree of Thoughts - 思维树）**
- 适用于需要多角度分析、方案对比的复杂决策问题
- 生成多个候选方案 → 评估打分 → 选择最优 → 精细化输出
- 提供全面、深入的分析和解决方案

## 工作流程

```
用户输入
   ↓
意图识别（IntentCmp）
   ├─ 关键词匹配（快速）
   └─ 大模型识别（备用）
   ↓
选择对话链
   ├─ chatDirect（直接回答）
   ├─ chatCoT（思维链）
   └─ chatToT（思维树）
   ↓
执行对应组件
   ↓
返回结果
```

## API 接口

### 1. 普通对话接口

**POST /chat**

请求体：
```json
{
  "text": "请帮我分析一下这个问题..."
}
```

响应：
```json
{
  "result": "最终回答内容",
  "intent": "识别到的意图",
  "chain": "使用的对话链"
}
```

### 2. GET 兼容接口

**GET /chat?text=xxx**

与 POST 接口功能相同，支持 GET 参数方式。

### 3. 流式对话接口

**GET /chat/stream?text=xxx&modelEnum=SILICON_FLOW**

返回 Server-Sent Events (SSE) 流式数据，适合需要打字机效果的场景。

参数：
- `text`: 用户输入的文本（必填）
- `modelEnum`: 模型类型，可选值：
  - `SILICON_FLOW`（默认）
  - `OPENROUTER`
  - `OPENAI`
  - `LOCAL`

## 意图配置

在 `application-ai.yml` 中配置意图分类和关键词：

```yaml
shiyu:
  intent:
    categories:
      default:
        - id: "direct_greeting"
          name: "问候寒暄"
          type: "DIRECT"
          content: "用于处理日常问候、寒暄等简单对话"
          keywords: ["你好", "您好", "hello"]
          chain-to-call: "chatDirect"
        
        - id: "cot_reasoning"
          name: "逻辑推理"
          type: "COT"
          content: "需要逐步推理的问题，如数学题、逻辑题等"
          keywords: ["为什么", "如何证明", "推理"]
          chain-to-call: "chatCoT"
        
        - id: "tot_decision"
          name: "多方案决策"
          type: "TOT"
          content: "需要从多个角度分析并提供多种解决方案的问题"
          keywords: ["方案", "选择", "决策", "对比"]
          chain-to-call: "chatToT"
```

## LiteFlow 链配置

配置文件位于：`src/main/resources/liteflow/chain/chain.json`

```json
{
  "flow": {
    "chain": [
      {
        "name": "chatFlow",
        "value": "THEN(INTENT, CHAIN_EXECUTE)"
      },
      {
        "name": "chatDirect",
        "value": "THEN(CHAT_DIRECT)"
      },
      {
        "name": "chatCoT",
        "value": "THEN(CHAT_COT)"
      },
      {
        "name": "chatToT",
        "value": "THEN(CHAT_TOT)"
      }
    ]
  }
}
```

## 使用示例

### 示例 1：简单问候（触发 Direct）

```bash
curl -X POST http://localhost:9001/chat \
  -H "Content-Type: application/json" \
  -d '{"text": "你好"}'
```

### 示例 2：逻辑推理问题（触发 CoT）

```bash
curl -X POST http://localhost:9001/chat \
  -H "Content-Type: application/json" \
  -d '{"text": "证明勾股定理"}'
```

### 示例 3：多方案决策（触发 ToT）

```bash
curl -X POST http://localhost:9001/chat \
  -H "Content-Type: application/json" \
  -d '{"text": "我想学习编程，应该选择 Python 还是 Java？"}'
```

### 示例 4：流式输出

```bash
curl http://localhost:9001/chat/stream?text=你好
```

## 扩展新意图

### 步骤 1：创建新的 LiteFlow 组件

```java
@LiteflowComponent("CHAT_REACT")
public class ChatReActCmp extends NodeComponent {
    @Override
    public void process() {
        // 实现 ReAct 模式的逻辑
    }
}
```

### 步骤 2：在 chain.json 中添加新链

```json
{
  "name": "chatReAct",
  "value": "THEN(CHAT_REACT)"
}
```

### 步骤 3：在配置文件中添加意图定义

```yaml
- id: "react_search"
  name: "搜索查询"
  type: "REACT"
  content: "需要搜索外部信息的问题"
  keywords: ["搜索", "查询", "查找"]
  chain-to-call: "chatReAct"
```

## 技术栈

- **Spring Boot 3.x**
- **Spring AI** - 大模型集成框架
- **LiteFlow** - 流程编排引擎
- **Project Lombok** - 代码简化

## 注意事项

1. **API Key 配置**：确保在 `application-ai.yml` 中配置了有效的 API Key
2. **模型选择**：不同平台支持的模型可能不同，请参考各平台文档
3. **超时设置**：复杂推理可能耗时较长，建议合理设置超时时间
4. **错误处理**：所有组件都设置了 `isContinueOnError=true`，确保流程不会因单点故障中断

# 模块功能索引

后端由根 Maven POM 聚合 29 个叶子模块。每个模块 README 分别说明功能、使用前提、用法、协作边界、内部依赖和定向测试命令；本页用于定位能力并选择合适的接入路径。事实以当前源码、POM 和运行配置为准，模块名不等于某项外部服务已经部署。

## 先确认使用环境

1. 本地默认运行需要 JDK 21、Maven 和可写的应用数据目录（`APP_HOME` 或 `-Dapp.home`）。默认组合使用 H2、JVector、本地文件和单进程短期状态；同一嵌入式数据目录不能由多个进程同时写入。
2. HTTP 接口需先完成 IAM 认证。功能权限码、当前租户与对象归属是不同层次的检查：拿到接口权限不意味着可以访问任意租户、知识空间或课程。
3. 领域间 Java 调用优先依赖目标领域的 `*-contract`；运行时应用还需装配对应 `*-implementation`。只加 Maven contract 不会创建 Bean、数据库表或外部 provider。
4. 可选能力先检查对应 README 的前提：教育模块开关、模型地址/凭证、索引维度、Redis/S3/Kafka 服务及构建 profile。切换 provider 不会自动迁移旧数据。

## 三条常用上手路径

| 目标 | 先准备 | 操作入口 | 后续验证 |
| --- | --- | --- | --- |
| 本地启动并查看接口 | JDK 21、Maven、独占且可写的 `APP_HOME` | 从仓库根目录运行 Bootstrap；开发构建查看 `/v3/api-docs` | 确认应用就绪、H2 基线和当前启用模块的实际路由。 |
| 创建教育课程 | 启用 `shiyu.modules.education.enabled`，登录并取得当前租户的模块访问权和 `edu:course:create` | `POST /api/education/course`；查看课程用 `GET /api/education/course`（`edu:course:list`） | 在当前租户下读取新课程，再建立章节/题目；不把关闭模块解释为删除数据。 |
| 在 Agent 中使用知识检索 | 创建有访问权的知识空间，上传文档并等待入库与索引完成；嵌入模型与向量维度匹配 | Agent 配置知识节点；模块间通过 `KnowledgeRetrievalService` 和可信 `ActorContext` 请求检索 | 检查命中来源、引用、空间成员权限及运行轨迹，不能仅凭相似度分数判断可见性。 |

具体请求体、响应字段和实际启用的 HTTP 方法以运行时 `/v3/api-docs` 为准；上表只列已核对的入口和权限前提。

## 常见协作路径

- **HTTP 请求：** `shiyu-ai-bootstrap` 装配 `shiyu-ai-web`；应用层验证登录态并构造主体上下文；领域 Controller 声明操作权限，领域服务校验对象归属；Flex/JDBC、文件和向量适配各自执行存储隔离。
- **生成请求：** conversation 建立运行并组织 Prompt，经组合层接入 governance 的准入和用量记录；Agent/Model/Knowledge/Memory/Tooling 分别承担执行、推理、检索、记忆和工具职责。
- **教育业务：** education implementation 拥有课程与学习状态，通过 Agent、Model、Knowledge 等 contract 使用平台能力；`shiyu.modules.education.enabled` 控制装配，不转移数据所有权。
- **新租户：** IAM 负责租户和角色状态，再通过 IAM/Knowledge 的 provisioning contract 初始化相应默认设置；普通仓储在可信 `TenantScope` 下访问数据。

新增模块时应先确定数据与业务规则的归属，再决定是否需要独立 contract；不要仅因存在新 Controller 就新增一个可执行 application。

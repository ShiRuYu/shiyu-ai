# 外部基础设施切换

> 文档基线：2026-09-11。配置键、脚本和实现以当前源码为准。

应用仍以单体方式运行，业务代码只依赖现有端口。基础设施实现由配置选择，修改配置并重启应用即可切换；不会在运行时复制数据，也不会自动把空的外部服务当成已有数据源。

## Provider 配置

| 设施 | 配置键 | 可选值 | 默认值 |
| --- | --- | --- | --- |
| 数据库 | `shiyu.infrastructure.database.provider` | `h2`、`mysql`、`postgresql` | `h2` |
| 文件 | `shiyu.infrastructure.file.provider` | `local`、`s3`、`minio` | `local`，兼容 `shiyu.storage.type` |
| 向量 | `shiyu.infrastructure.vector.provider` | `inmemory`、`jvector`、`pgvector` | `jvector`，兼容 `shiyu.vector-store.type` |
| Redis | `shiyu.infrastructure.redis.provider` | `disabled`、`redis` | `disabled` |
| 事件 | `shiyu.infrastructure.event.provider` | `in-process`、`postgres-outbox`、`kafka` | `in-process` |

连接地址、账号和密钥只从环境变量或密钥管理系统注入。旧的 `shiyu.storage.type` 与 `shiyu.vector-store.type` 仍然有效；新的 provider 配置存在时优先使用新的配置。

`local`、`s3` 和 `minio` 是新的文件 provider 值；历史配置中的 `aliyun-oss`、`tencent-cos` 仍可通过兼容的 `shiyu.storage.type` 使用，迁移到新配置时应先完成对象 key 与 checksum 校验。

## 常用启动组合

本地开发保持默认配置：H2、local、JVector、内存 Redis 状态和进程内事件。

PostgreSQL + S3 + pgvector：

```powershell
$env:SHIYU_INFRA_DATABASE_PROVIDER = "postgresql"
$env:SHIYU_INFRA_FILE_PROVIDER = "s3"
$env:SHIYU_INFRA_VECTOR_PROVIDER = "pgvector"
$env:SHIYU_DB_URL = "jdbc:postgresql://db.example/shiyu"
$env:SHIYU_DB_USERNAME = "shiyu"
$env:SHIYU_DB_PASSWORD = "<secret>"
$env:SHIYU_STORAGE_S3_ENDPOINT = "https://s3.example"
$env:SHIYU_STORAGE_S3_BUCKET = "shiyu"
$env:SHIYU_STORAGE_S3_ACCESS_KEY = "<secret>"
$env:SHIYU_STORAGE_S3_SECRET_KEY = "<secret>"
java -jar shiyu-ai-bootstrap.jar --spring.profiles.active=postgresql,external-infra
```

MinIO 只需将文件 provider 改为 `minio`，并设置 `SHIYU_STORAGE_MINIO_*` 变量。Redis 需要显式开启：

```powershell
$env:SHIYU_INFRA_REDIS_PROVIDER = "redis"
$env:SHIYU_REDIS_URL = "redis://redis.example:6379/0"
```

`redis` 不可用时锁、租约和限流会快速失败；`disabled` 使用当前进程内实现，不承担跨实例一致性。

## 数据库切换规则

H2 由 `DatabaseInitializer` 幂等安装本地基线。MySQL 和 PostgreSQL 只做连接、数据库产品、基线版本、种子版本、表集合和关键列校验，要求外部数据库已经完成完整基线（`COMMON_SCHEMA_BASELINE`，版本 `4`，种子 `system-ai`）。校验失败会拒绝启动。

切换前必须由运维执行 dump/restore 或受控迁移，并在停机窗口验证行数、索引和约束；修改 provider 配置本身不会迁移任何数据。

仓库提供 [PostgreSQL 基线脚本](../scripts/database/postgresql/baseline-schema.sql)、[基线种子脚本](../scripts/database/postgresql/baseline-seed.sql)、[pgvector 对象脚本](../scripts/database/postgresql/pgvector.sql)、[outbox 对象脚本](../scripts/database/postgresql/event-outbox.sql) 和 [数据库迁移脚本](../scripts/database/migrate.ps1)。脚本不包含凭据，执行前由密钥管理系统注入客户端环境变量。

## 文件迁移

local 到 S3/MinIO 的一次性迁移默认关闭。显式设置以下变量后启动一次应用，迁移程序会保留原对象 key，成功后再关闭开关：

```powershell
$env:SHIYU_STORAGE_MIGRATION_ENABLED = "true"
$env:SHIYU_STORAGE_MIGRATION_SOURCE_PATH = "E:\data\files"
$env:SHIYU_STORAGE_MIGRATION_DESTINATION_PROVIDER = "s3" # 或 minio
$env:SHIYU_STORAGE_MIGRATION_NAMESPACE = "tenant/1"
```

元数据仍以数据库为准。迁移完成后先抽样下载并核对 checksum，再把 `SHIYU_INFRA_FILE_PROVIDER` 切换到目标 provider。

## 向量与事件

`pgvector` 启动时要求实际 JDBC 数据库是 PostgreSQL，并自动检查 `vector` 扩展、向量表和维度；与 H2/MySQL 组合会直接失败。向量索引切换前应停止写入并按租户、空间重新执行现有知识索引重建接口，不能把空的 pgvector 表直接用于生产。

`postgres-outbox` 与 `kafka` 都把事件先写入同一数据库的 `shiyu_event_outbox`。Kafka 只在 provider 为 `kafka` 时创建 producer；进程内生产和消费仍在同一个应用进程内，不会拆分服务。outbox relay 会记录投递次数和错误，达到 `SHIYU_KAFKA_MAX_ATTEMPTS` 后转发到 `SHIYU_KAFKA_DEAD_LETTER_TOPIC`；消费端可注入 `EventConsumptionDeduplicator`，用同库 inbox 主键按事件 id 去重。

## 回滚

保留旧 provider 的数据和凭据，出现外部设施故障时把对应 provider 改回 `local`、`jvector`、`disabled` 或 `in-process` 并重启。数据库回滚仍需使用数据库级 restore，不能依靠应用启动器覆盖已有数据。

# ShiYu AI 后端技术文档

> 面向开发者的架构速查。详细接口、字段、权限和部署步骤分别由参考文档、源码和运维手册维护。

## 1. 技术栈

| 领域 | 当前实现 |
| --- | --- |
| 运行时 | Java 21+，Maven `--release 21` |
| Web / 应用 | Spring Boot 4.1、Spring MVC、SpringDoc |
| AI / Agent | Spring AI、LangChain4j、LangGraph4j |
| 数据访问 | MyBatis-Flex 1.11.7；H2 默认，支持 MySQL/PostgreSQL |
| 认证 | Sa-Token 1.45 |
| 向量 | JVector 默认，支持 InMemory、pgvector |
| 存储与状态 | local 默认，支持 S3/MinIO；Redis 可选 |

## 2. 总体架构

```text
应用壳（启动、认证 HTTP、异常、装配）
        ↓
领域 implementation（服务、模型、Repository、适配器）
        ↓
领域 contract / Shared Kernel
        ↓
MyBatis、文件、向量、线程和事件 provider
```

目录约定：`applications` 放启动和公共 HTTP，`domains` 放平台领域，`business/education` 放独立业务，`infrastructure` 放技术支持，`shared` 放跨域公共类型。每个领域使用 `contract` + `implementation` 双模块。

跨领域只能依赖 contract、事件或基础设施端口；禁止 implementation 互相依赖、跨域访问 Repository/Mapper、跨领域 SQL JOIN，以及从领域层读取 `UserContextHolder`。

## 3. 请求、安全与租户

```text
Authorization Bearer Token
  → 认证过滤器 / UserContextInterceptor
  → ActorContext + TenantScope
  → Controller 参数与权限校验
  → Application / Domain Service
  → Repository / Port
  → Result<T> 或 SSE
```

- 普通 Flex 查询、更新和删除由框架生成租户条件，Repository 仍校验参数与当前作用域一致。
- Flex 新增由框架补齐空租户；显式租户必须与作用域一致。
- JDBC、原生 SQL、文件和向量索引必须显式携带可信租户条件或命名空间。
- 跨租户操作先做授权，再进入目标作用域，结束后恢复原作用域；缺少作用域时拒绝持久化。

详见 [安全与租户隔离审计](安全与租户隔离审计.md)。

## 4. API 契约

普通 REST 接口使用 `Result<T>`，成功业务码为 `200`；调用方同时判断 HTTP 状态和业务码。领域路径保持 `/api/{domain}`，教育路径保持 `/api/education/**`。

| 能力 | 约定 |
| --- | --- |
| 分页 | 主要参数为 `pageNum`、`pageSize`；前端 facade 负责适配 UI 参数。 |
| SSE | 使用 `text/event-stream`，事件携带运行标识和序号，支持续传与取消。 |
| 上传 | 使用文件 facade 处理分片、合并、取消和进度，不将二进制塞进普通 JSON。 |
| 幂等 | 创建会话、消息生成等可重试命令使用 `Idempotency-Key`。 |
| 版本 | Knowledge 当前通过请求头 `version: 1`，不在 URL 增加版本段。 |

逐条路径和 schema 只维护在 [API接口参考](参考/API接口参考.md) 与 OpenAPI 快照中。

## 5. 数据与存储

`app.home` 优先取系统属性或 `APP_HOME`；本地开发默认 `runtime/dev`。运行数据包括：

```text
${app.home}/data/
├─ db/       H2 数据库
├─ files/    本地文件
├─ vector/   向量索引
└─ backups/  备份
```

各领域维护自己的 H2 baseline；应用启动校验版本、表集合和关键列，不替生产库执行隐式迁移。MySQL/PostgreSQL 由外部脚本和 profile 提供。

文件元数据在数据库，内容在 local/S3/MinIO；向量命名空间必须包含租户和知识空间；Redis 默认关闭，事件默认进程内，可选 outbox/Kafka。切换 provider 前先完成迁移、校验和回滚演练。

## 6. 默认启动与配置

完整包和平台包都支持无额外参数启动：`dev`、9000、H2、事务开关和本地 provider 均有默认值。环境变量或外部配置可覆盖端口、profile、数据库、文件、向量、Redis 和模型平台。

配置文件职责：

- `application.yml`：公共默认值、profile 和 Web 配置。
- `application-h2.yml` / `application-mysql.yml` / `application-postgresql.yml`：数据库 profile。
- `application-ai.yml`：模型平台环境变量入口。
- `config/config.yml`：可选本地模型配置，不提交真实密钥。

IntelliJ 的 Project SDK、模块 SDK 和 Maven Runner 应统一使用 JDK 21+；`.idea` 是本地状态，不提交到 Git。

## 7. 开发约定与验证

- 从仓库根目录构建完整 Maven reactor，不依赖本地旧模块。
- Controller 负责协议和校验，Service/Domain 负责业务规则，Repository 负责持久化适配。
- 表、字段、菜单、权限或 API 变化必须同步更新源码、生成参考文档、测试和规范说明。
- 最小门禁：`mvn test`、`python scripts/docs/verify_documentation.py`、架构检查和 `git diff --check`。
- 发布包门禁：`mvn -Pprod -DskipTests -Djacoco.skip=true clean package`；跳过测试只允许在测试已独立通过时使用。

## 8. 前后端契约审计

契约检查将 Spring 实际注册的业务路由与运行时 OpenAPI 比对，再比对导出的快照及 API 文档中的 HTTP 方法与路径集合；文档与快照数量相等不能代替接口集合一致。分组扫描和教育动态前缀由 Bootstrap 集成测试覆盖。数据库 baseline 和 seed 继续用于交叉验证表、菜单和权限数量。这些检查不能替代真实模型、对象存储、网关或生产数据库的全链路验证。统计数字以 `scripts/docs/verify_documentation.py` 当前输出为准。

## 二、shiyu-ai-dal（统一数据访问层）

### 架构层次

`
Controller/Service
    ↓ BO
Repository (业务数据接口)
    ↓
Mapper (MyBatis-Flex / MyBatis-Plus)
    ↓ DO / QueryWrapper
Database (H2 / MySQL)
`

### Repository 模式

每个业务域遵循统一四层：

| 层 | 命名示例 | 说明 |
|----|---------|------|
| BO | AgentExecutionBO | 业务对象，供 Service 使用 |
| DO | AgentExecutionDO | 数据对象，与表结构一一对应 |
| Mapper | AgentExecutionMapper | MyBatis-Flex Mapper |
| Repository | AgentExecutionRepository | 封装 Mapper，对外暴露 BO |

### 数据转换

使用 **MapStruct Plus**（@AutoMapper 注解）自动完成 BO↔DO 转换。

## 三、shiyu-ai-model（AI 模型适配层）

### 核心接口

#### ModelAdapter

``java
public interface ModelAdapter {
    String getPlatformType();
    ChatModel getChatModel(String modelName);
    StreamingChatModel getStreamingChatModel(String modelName);
    String getDefaultModelName();
    boolean isAvailable();
    void clearCache();
}
``

#### 实现类

| 类名 | 适用平台 | 特点 |
|------|---------|------|
| GenericPlatformAdapter | OpenAI / DeepSeek / OpenRouter / SiliconFlow | 通用 HTTP API 适配 |
| OllamaPlatformAdapter | Ollama 本地模型 | 本地部署 |

#### ModelManager

管理所有 ModelAdapter 的生命周期：
- 启动时从 DB 加载平台配置
- 支持运行时重新加载
- 熔断/限流/负载均衡包装
- 支持默认平台选择

### ChatEngine

``java
public interface ChatEngine {

    ChatResponse chatWithMemory(String sessionId, ChatRequest request);       // 带记忆对话
    Flux<ChatResponse> streamWithMemory(String sessionId, ChatRequest request); // 带记忆流式
}
``

### 弹性能力

## 四、shiyu-ai-agent（Agent 核心模块）

### 4.1 架构总览

`
Controller 层
├── AgentDefinitionController  (Agent 定义 CRUD)
├── AgentVersionController     (版本管理)
├── ExecutionController         (执行生命周期)
└── IntentDefController         (意图定义)

Service 层
├── AgentService           (109 行，只做定义管理)
├── AgentVersionService
├── ExecutionHistoryService
├── AuditService
├── IntentDefService
└── IntentService

Runtime 层
├── AgentRuntime            (执行生命周期接口)
├── AgentRuntimeImpl        (执行管理实现)
└── AgentExecutor           (基于 LangGraph4j 的执行引擎)
`

### 4.2 执行流程

`
1. ExecutionController.execute(agentId, input)
2. AgentRuntimeImpl.execute(agentId, version, input)
   ├── createExecution() → Execution(PENDING)
   ├── AgentStateMachine.transition(PENDING → RUNNING)
   ├── eventPublisher.publish(AgentExecutionStartedEvent)
   ├── AgentExecutor.executeAgent(definition, version, input, execution)
   │   ├── Graph.compile() → CompiledGraph
   │   └── CompiledGraph.invoke(input)
   │       └── Node1 → Node2 → ... → NodeN
   │       └── 每个 Node: process() → 返回结果
   ├── checkpointManager.createCheckpoint()
   ├── execution.complete(result)
   ├── saveExecution(execution)
   ├── eventPublisher.publish(AgentExecutionCompletedEvent)
   └── cleanupExecution(execution)
3. 返回 Execution 给 Controller
`

### 4.3 节点系统

**支持的节点类型（15 种）**：

| 枚举值 | 节点类 | 用途 |
|--------|--------|------|
| DEFAULT | DefaultNode | 默认空节点 |
| LLM_CALL | LlmCallNode | 调用大语言模型 |
| RAG_RETRIEVAL | RagRetrievalNode | 知识库检索 |
| RAG_ENHANCEMENT | RagEnhancementNode | 检索结果重排增强 |
| MEMORY_SHORT_TERM | ShortTermMemoryNode | 短时记忆处理 |
| MEMORY_LONG_TERM | LongTermMemoryNode | 长时记忆存储 |
| MEMORY_RETRIEVAL | MemoryRetrievalNode | 记忆检索召回 |
| TOOL_CALL | ToolCallNode | MCP 工具调用 |
| INTENT | IntentNode | 用户意图识别 |
| CONDITION | ConditionNode | 条件分支路由 |
| TRANSFORM | TransformNode | 数据格式转换 |
| OUTPUT_FORMAT | OutputFormatNode | 输出格式化 |
| AGENT_CALL | AgentCallNode | 子 Agent 调用 |
| ABILITY_QUERY | — | 教育能力查询 |
| EDUCATION_TEACH | — | 教育授课 |
| EDUCATION_PRACTICE | — | 教育练习 |
| SCORE_ANALYSIS | — | 教育成绩分析 |
| REVIEW_SCHEDULE | — | 教育复习排程 |
| PREREQ_CHECK | — | 教育前置检查 |

### 4.4 Graph 编排引擎

基于 **LangGraph4j** 的 DAG 执行引擎，支持：

| 特性 | 说明 |
|------|------|
| DAG 图 | 有向无环图节点编排 |
| 条件边 | 根据运行时条件选择分支 |
| 状态通道 | 自定义 AgentState Channel |
| 流式执行 | Flux<NodeOutput<AgentState>> |
| 循环检测 | DFS 环路检测 |
| 可达性分析 | 自动发现不可达节点 |
| 缓存编译 | 编译后 CompiledGraph 缓存 |
| 校验器 | 节点/边/条件完整性校验 |

### 4.5 状态机

**AgentStateMachine** 管理执行状态转换：

`
PENDING ──→ RUNNING ──→ COMPLETED
  │            │           FAILED
  │            ├──→ PAUSED ──→ RUNNING
  └──→ CANCELLED
`

### 4.6 Agent 生命周期

| 状态 | 说明 |
|------|------|
| CREATED | 刚创建 |
| DEPLOYED | 已部署（可执行） |
| DISABLED | 已停用 |
| ARCHIVED | 已归档 |

## 五、shiyu-ai-knowledge（知识库 / RAG 模块）

### 核心流程

`
文档上传
    ↓
DocumentIngestionService
├── DocumentParser (PDF/Word/Markdown)
├── ChunkSplitter (中文分块)
├── EmbeddingService (向量化)
└── VectorStore (写入向量库)
    ↓
RagOrchestrator (检索编排)
├── EmbeddingService (Query 向量化)
├── VectorStore (向量检索)
├── Reranker (重排)
└── 结果融合
    ↓
返回检索结果
`

### 文档解析器

| 解析器 | 格式 | 说明 |
|--------|------|------|
| PdfDocumentParser | PDF | PDF 文本提取 |
| WordDocumentParser | DOCX | Word 文档解析 |
| MarkdownDocumentParser | MD | Markdown 解析 |

### RAG 组件

| 组件 | 类名 | 说明 |
|------|------|------|
| 分块器 | ChineseChunkSplitter | 中文优化分词 |
| 检索服务 | RagService / RagServiceImpl | RAG 检索接口 |

## 七、shiyu-ai-vector（独立向量存储模块）

向量模块保持独立，不与 Model 合并。Model 负责 Embedding/Chat/Rerank Provider，Vector 负责 JVector/InMemory 索引实现；Knowledge 通过抽象边界使用它。

### 架构

`
VectorStore (接口)
├── search(vector, topK)
├── add(id, vector, metadata)
├── remove(id)
└── clear()

实现类
├── InMemoryVectorStore (本地内存)
└── JVectorStore (JVector 实现)

VectorStoreFactory (工厂)
├── create(type) → VectorStore
└── type: IN_MEMORY / JVECTOR
`

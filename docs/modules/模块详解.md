# 模块详解

> 各模块职责、关键类、核心流程说明（基于 2026-08-04 最新代码）

---

## 总体分层

项目按 **业务 / 平台 / 基础设施** 三层组织，依赖方向单向向下：

```
🎯 业务层         shiyu-ai-education · shiyu-ai-record
⚙️ 平台层         shiyu-ai-agent ⭐ · auth · model · knowledge · vector · memory · tool · usage · plugin
🧱 基础设施层      shiyu-common(5) · shiyu-ai-dal · shiyu-ai-web · shiyu-ai-bootstrap
```

每个业务/平台模块内部统一采用 DDD 结构：

```
api/                   对外 API 模型（request / response）
application/           应用服务 / 组装器（assembler）
domain/model/          业务对象 BO（从 dal 迁入）
port/repository/       仓储接口（依赖倒置，由 dal 实现）
service/               业务服务
```

## 二、shiyu-ai-dal（数据访问实现层）

### 角色定位

DDD 重构后，**BO 与仓储接口已迁入各领域模块**（`domain/model` + `port/repository`），`shiyu-ai-dal` 退化为纯实现层：

- 只保留 **DO（dataobject）+ Mapper + Repository 实现**
- Repository 实现通过 `@AutoMapper`（MapStruct Plus）完成 DO↔BO 转换
- 依赖各领域模块的 `port/repository` 接口，实现"依赖倒置"

### 目录结构

```
shiyu-ai-dal/src/main/java/com/shiyu/ai/dal/
├── agent/ auth/ education/ knowledge/ memory/ model/ record/ usage/   # 各域 DO/Mapper/Repo 实现
├── common/              # 公共表（字典等）
├── config/              # 租户工厂、数据库初始化、Flyway 装配
├── datasource/          # 数据源配置
├── retention/           # 数据保留策略（DataRetentionService）
├── storage/             # 存储元数据（JdbcStorageMetadataStore）
└── util/
```

### 数据流转

```
Controller/Service → BO → Repository(接口) → Repository(实现/dal)
    ↓                                      ↓
  VO ←── MapStruct ←────────────────── Mapper (MyBatis-Flex)
                                            ↓
                                         DO → Database (H2/MySQL)
```

### Flyway

30 个迁移脚本（V001–V026 + 域分目录 + 种子数据 R__/Z__），按域组织：agent/auth/common/education/knowledge/memory/observation/record/storage/vector。

## 四、shiyu-ai-agent（平台核心：Agent 引擎）

### 4.1 架构总览

```
⭐ 平台核心，通用图编排引擎（教育相关代码已迁出至 education 模块）

Service 层
├── AgentService / AgentVersionService / IntentDefService / IntentService
├── ExecutionHistoryService / AuditService / TimelineService
├── AgentAdminService（管理类操作）

Runtime 层
├── AgentRuntime / AgentRuntimeImpl   (执行生命周期)
├── AgentExecutor                     (基于 LangGraph4j 的执行引擎)
├── AgentBuilder / StateGraphBuilder  (图构建)

Graph / Node 层
├── Graph / NodeFactory / BaseNode
├── 13 种通用节点 + 教育节点由 education 模块提供 Creator 注册

领域层（DDD）
├── domain/model    — AgentDefBO / AgentVersionBO / AgentExecutionBO / NodeExecutionBO /
│                      AgentCheckpointBO / IntentDefBO / AuditLogBO / ExecutionTimelineBO
└── port/repository — AgentDefRepository / AgentVersionRepository / AgentExecutionRepository /
                       NodeExecutionRepository / AgentCheckpointRepository / IntentDefRepository /
                       AuditLogRepository / ExecutionTimelineRepository
```

### 4.2 执行流程

```
1. ExecutionController.execute(agentId, input)
2. AgentRuntimeImpl.execute(agentId, version, input)
   ├── createExecution() → Execution(PENDING)
   ├── AgentStateMachine.transition(PENDING → RUNNING)
   ├── eventPublisher.publish(AgentExecutionStartedEvent)
   ├── AgentExecutor.executeAgent(definition, version, input, execution)
   │   ├── Graph.compile() → CompiledGraph
   │   └── CompiledGraph.invoke(input)
   │       └── Node1 → Node2 → ... → NodeN
   │       └── 每个 Node: process() → 返回结果
   ├── checkpointManager.createCheckpoint()
   ├── execution.complete(result)
   ├── saveExecution(execution)
   ├── eventPublisher.publish(AgentExecutionCompletedEvent)
   └── cleanupExecution(execution)
3. 返回 Execution 给 Controller
```

### 4.3 节点系统（NodeType 枚举）

**通用节点（13 种）**：

| 枚举值 | 节点类 | 用途 |
|--------|--------|------|
| DEFAULT | DefaultNode | 默认空节点 |
| INTENT | IntentNode | 用户意图识别 |
| RAG_RETRIEVAL | RagRetrievalNode | 知识库检索（支持空间授权） |
| RAG_ENHANCEMENT | RagEnhancementNode | 检索结果增强 |
| MEMORY_SHORT_TERM | ShortTermMemoryNode | 短期记忆读写 |
| MEMORY_LONG_TERM | LongTermMemoryNode | 长期记忆存储 |
| MEMORY_RETRIEVAL | MemoryRetrievalNode | 跨会话记忆检索 |
| LLM_CALL | LlmCallNode | 调用大语言模型 |
| TOOL_CALL | ToolCallNode | MCP 工具调用 |
| CONDITION | ConditionNode | 条件分支路由 |
| TRANSFORM | TransformNode | 数据格式转换 |
| OUTPUT_FORMAT | OutputFormatNode | 输出格式化 |
| AGENT_CALL | AgentCallNode | 子 Agent 调用 |

**教育域节点（6 种，由 education 模块实现并注册）**：

| 枚举值 | 节点类（education/agent） | 用途 |
|--------|--------------------------|------|
| ABILITY_QUERY | AbilityQueryNode | 能力值查询 |
| EDUCATION_TEACH | TeachNode | 教学讲解 |
| EDUCATION_PRACTICE | PracticeNode | 练习出题 |
| SCORE_ANALYSIS | ScoreAnalysisNode | 评分分析 |
| REVIEW_SCHEDULE | ReviewScheduleNode | 复习排程 |
| PREREQ_CHECK | PrereqCheckNode | 前置知识检查 |

> 教育节点的 Creator（`*NodeCreator`）位于 `shiyu-ai-education/agent/node/creator`，通过 `NodeFactory` 注册进引擎 —— **平台节点与业务节点物理分离**。

### 4.4 Graph 编排引擎

基于 **LangGraph4j** 的 DAG 执行引擎，支持：

| 特性 | 说明 |
|------|------|
| DAG 图 | 有向无环图节点编排 |
| 条件边 | 根据运行时条件选择分支 |
| 状态通道 | 自定义 AgentState Channel |
| 流式执行 | Flux<NodeOutput<AgentState>> |
| 循环检测 | DFS 环路检测 |
| 可达性分析 | 自动发现不可达节点 |
| 缓存编译 | 编译后 CompiledGraph 缓存 |
| 校验器 | 节点/边/条件完整性校验 |

### 4.5 执行状态机（ExecutionStatus）

```
PENDING ──→ RUNNING ──→ COMPLETED
  │            │           FAILED
  │            ├──→ PAUSED ──→ RUNNING
  └──→ CANCELLED
```

### 4.6 Agent 生命周期（AgentState）

| 状态 | 说明 |
|------|------|
| CREATED | 刚创建 |
| DEPLOYED | 已部署（可执行） |
| DISABLED | 已停用 |
| ARCHIVED | 已归档 |

### 4.7 审计与执行时间线

- `AuditService` + `AuditEventListener`：审计操作落库（AuditLogBO）
- `TimelineService` + `TimelineEventListener`：执行时间线（ExecutionTimelineBO）

## 七、shiyu-ai-vector（独立向量存储模块）

向量模块保持独立，不与 Model 合并。Model 负责 Embedding/Chat/Rerank Provider，Vector 负责向量存储抽象及 JVector/InMemory 实现；Knowledge 和 Memory 只通过公共接口使用它。

### 架构

```
VectorStore (单个向量空间接口)
├── upsert / upsertBatch
├── search(ANN / EXACT、过滤、阈值)
├── delete / deleteBatch / rebuild
└── flush / close

VectorStoreProvider (后端与空间工厂接口)   🆕 统一 Provider API
├── open(namespace, dimension, dataDir)
├── drop(namespace)
└── type()

实现类
├── InMemoryVectorStore (本地内存)
└── JVectorStore (JVector HNSW)

ConfiguredVectorStoreProvider (默认适配器)
├── 配置后端: inmemory / jvector
├── 按 tenant / space / version 隔离索引目录
└── Knowledge 的 Chunk 与向量事实源保存在 H2，索引可重建
```

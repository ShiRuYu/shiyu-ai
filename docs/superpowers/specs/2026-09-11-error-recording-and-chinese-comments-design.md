# 错误记录与中文注释门禁设计

## 背景

本次构建失败来自 `opennlp-tools-2.5.9.jar` 清单中的 `Class-Path` 指向不存在的同目录依赖。`javac` 将该路径诊断为警告，项目的 `-Werror` 又把警告升级为编译失败。错误本身与业务代码无关，但如果没有记录和预检，同类依赖清单问题会在构建阶段再次出现。

同时，项目中的接口类型和关键实现注释不完整，部分自然语言注释仍为英文。注释需要成为可维护的中文契约，而不是只在一次扫描中人工确认。

## 目标

1. 记录本次错误的现象、根因、复现方式、修复方式和预防规则。
2. 在构建前检查项目实际使用的 JAR 清单，发现缺失的 `Class-Path` 目标时立即失败。
3. 为所有生产接口类型补充中文类型级 JavaDoc。
4. 为公共 DTO、枚举、控制器、应用服务和关键领域类型补充中文说明。
5. 扫描项目自有源代码、配置、脚本和文档，将自然语言注释统一为中文；保留类名、协议名、命令、路径、URL、配置键和代码片段等技术标识。
6. 把检查接入本地脚本测试和 CI，防止新代码回退。

## 范围与排除

- 扫描后端 `modules`、`tests`、`scripts`、`.github`、项目文档，以及前端 `shiyu-ui` 中项目自有的源码和配置。
- 排除 `.git`、`target`、`node_modules`、构建产物、生成目录、第三方代码、数据库导出数据和历史备份。
- 不翻译 Java 标识符、包名、类名、方法名、注解名、协议字段、SQL 标识符、URL、版本号、Maven 坐标和命令参数。
- 本任务不改变 HTTP 路由、JSON 字段、数据库结构、业务规则或依赖版本。

## 方案

### 依赖清单预检

新增 `scripts/architecture/check_dependency_manifests.py`。脚本支持传入一个或多个 JAR，读取 `META-INF/MANIFEST.MF` 的 `Class-Path`，按 JAR 所在目录解析每个相对路径，并在目标不存在时输出文件、缺失项和建议。CI 先执行 Maven 离线依赖解析，再检查本项目使用的 OpenNLP JAR；本地可直接对任意 JAR 运行同一脚本。解析逻辑使用标准库，测试使用临时 JAR 夹具覆盖通过、缺失和多行清单。

`pom.xml` 中保留 `-Xlint:-path` 作为编译器防御性配置，但其说明改为中文。该选项不是根因修复的替代品，清单预检才是错误的早期反馈。

### 注释扫描门禁

新增 `scripts/architecture/check_chinese_comments.py`。扫描器拆出 JavaDoc、块注释、行注释以及 Markdown、YAML、XML、Python、TypeScript 等支持的注释区域，识别接口声明前的类型级 JavaDoc，并检测注释中的自然语言英文。标签、代码块、URL、技术标识和允许的缩写进入显式白名单；未知英文词仍需人工翻译或登记为技术词。

门禁输出缺失接口文档、英文自然语言注释和排除路径。脚本测试验证注释提取、接口判定、中文判定、白名单和排除目录。CI 在 Maven 验证前后都运行结构检查，使注释质量独立于编译器行为。

### 注释修复策略

- 每个接口声明紧邻位置增加描述其职责、输入输出或边界的中文 JavaDoc。
- 公共 DTO、枚举、控制器、应用服务和关键领域类型只补充能帮助调用者理解约束的说明，不为每个私有 getter 生成噪音。
- 将现有英文自然语言改写为中文，代码标识和协议文本保持原样。
- 生成报告记录扫描总量、已修复数量、白名单词和排除目录，便于后续审查。

## 验证与回滚

验证顺序为：脚本单元测试、依赖清单预检、注释门禁、架构脚本、`git diff --check`、严格 Maven 构建和现有测试。任一步失败都不得宣称完成。若注释门禁误报，只能扩大带理由的技术词白名单或修正解析器，不得关闭门禁。若构建失败，优先修复实际根因；`-Xlint:-path` 只用于兼容已知第三方清单问题。

### 2.2 ExamController — 补充 `GET /api/v1/exam` listAll

**现状**: 前端 `getExamList()` 调用 `GET /api/v1/exam` 获取全部试卷，但后端 ExamController 无此端点（仅有按 ID、按科目、按教师查询）

**需补充的端点**:

```java
@GetMapping
public Result<List<ExamResponse>> listAll() {
    List<ExamDO> list = examService.listAll();
    return Result.success(list.stream().map(this::toResponse).toList());
}
```

> 注：统一前缀后路径为 `/api/exam`

## 附录：前后端类型对齐

### 通用分页响应

```typescript
// 前端类型（应统一抽取）
interface PageResult<T> {
  items: T[];
  total: number;
  page: number;
  pageSize: number;
}

// 后端返回
{
  "code": 200,
  "message": "success",
  "data": {
    "list": [...],
    "total": 100,
    "page": 1,
    "pageSize": 20
  }
}
```

> **注意**: 前端 `requestClient` 使用 `responseReturn: 'data'` 自动解包，所以各 API 函数返回的是 `data` 内的内容。需确保后端统一使用 `PageResult` 结构。

### 当前 `PageResult` 前端不一致之处

| 文件 | 字段名 | 与其他文件对比 |
|------|--------|---------------|
| `system/user.ts` | `items` | ✅ 标准 |
| `agent/admin.ts` | `items` + `total` | ✅ 标准 |
| `common/dict.ts` | `items` + `total` | ✅ 标准 |
| `education/analytics.ts` | 无分页 | ⚠️ 返回非分页格式 |

### `requestClient` 自动解包影响

由于 `responseReturn: 'data'`，前端 API 函数返回值是后端 `data` 字段内的内容：

```typescript
// 后端返回:
{
  "code": 200,
  "data": {
    "items": [...],
    "total": 100
  }
}

// 前端接收:
{ items: [...], total: 100 }  // 自动解包，无外层 code/message
```

这意味着前端代码中不应再手动解包 `res.data`，但部分代码可能存在双重解包的风险。

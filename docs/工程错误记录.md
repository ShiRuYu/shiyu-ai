# 工程错误记录

## 2026-09-11：严格编译被第三方 JAR 清单路径警告阻断

### 现象

执行严格 Maven 构建时，`javac` 报告依赖清单中的路径无效；项目启用了 `-Werror`，因此警告被提升为源代码编译失败。报错位置看起来像编译器或注解处理器问题，但业务源码没有对应错误。

### 根因

`org.apache.opennlp:opennlp-tools:2.5.9` 的 `META-INF/MANIFEST.MF` 声明了 `Class-Path: slf4j-api-2.0.17.jar`。该文件发布包中没有同目录的目标 JAR，`javac` 因而产生路径警告。依赖本身仍能由 Maven 正常解析，问题只在第三方清单的相对路径声明。

### 复现

```powershell
javac -cp opennlp-tools-2.5.9.jar -Xlint:all -Werror Example.java
```

复现时可以看到无效路径警告；加入 `-Xlint:-path` 后警告不再升级为编译失败。这一参数是编译器兼容措施，不是对第三方清单的根因修复。

### 修复

1. 在 `pom.xml` 保留 `-Xlint:-path`，避免已知第三方清单诊断阻断源码编译。
2. 新增 `scripts/architecture/check_dependency_manifests.py`，在构建前读取实际使用的 JAR 清单，并对每个相对 `Class-Path` 目标做存在性检查。
3. CI 先执行 Maven 离线依赖解析，再检查 OpenNLP JAR；`slf4j-api-2.0.17.jar` 是本次已确认的第三方清单例外，必须通过显式 `--allow-missing` 登记。其他缺失项仍会在编译前失败，并输出 JAR、清单项和解析后的目标路径。

### 后续排查顺序

先确认失败项是否来自 `META-INF/MANIFEST.MF` 的相对路径，再确认 Maven 坐标和本地文件是否一致；只有确认是第三方清单误报后才使用编译器兼容参数。不得通过关闭全部 `-Xlint` 或删除 `-Werror` 隐藏其他真实警告。

## 2026-09-12：多行类型注解导致接口中文说明被误报

### 现象

中文注释门禁把已有中文类型说明的 `@interface` 报告为“接口缺少中文类型说明”。触发条件是接口声明前存在跨多行的 `@Target(...)` 等注解。

### 根因

扫描器从接口声明向上查找 Javadoc 时，只跳过以 `@` 开头的单行注解，没有识别注解参数的多行闭合行，因此把 `)` 当成了普通代码行。

### 修复

1. 反向扫描时记录注解括号余额，完整跳过跨多行的注解参数。
2. 新增多行注解接口的回归测试，防止后续再次误报。
3. CI 继续执行全仓中文注释门禁；门禁失败时必须修复扫描规则或实际注释，不得绕过检查。

## 2026-09-12：英文注释遗漏和模板化中文前缀

### 现象

部分旧的英文 JavaDoc、脚本注释和 SQL 注释未被原扫描器识别；已补充的注释又统一带有“中文接口说明：”或“中文说明：”前缀，阅读时像机器生成的占位文本。

### 根因

原规则只统计少量常见英文词，短标题和技术语境中的完整英文句子可能漏检；同时没有把模板前缀列为违规项。

### 修复

1. 扩展英文注释检测，覆盖短标题、单行 JavaDoc、XML/YAML/SQL/脚本注释，并保留明确的技术清单例外。
2. 删除全部实际注释中的模板前缀，改为直接表达职责、边界、来源或异常处理。
3. 新增英文短句、英文标题和模板前缀回归测试，CI 门禁持续阻断回归。

## 2026-09-12：功能注释占位语句

### 现象

部分类型和方法虽然已经有中文 JavaDoc，但内容仍是“此处说明当前模块”或“职责边界和调用约束”等泛化文本，无法帮助调用者理解真实职责。

### 修复

1. 按类型、方法、字段和配置项分别改写注释，直接说明职责、行为、参数含义和返回结果。
2. 为知识租户配置、教育应用服务及各领域端口、仓储、Mapper 补充语义化 JavaDoc。
3. 清理脚本、SQL、YAML 和 XML 中同类占位注释，并复查全仓源码无残留。

## 5. RogueMap 依赖策略

| 模块 | 依赖 | 用途 |
| --- | --- | --- |
| shiyu-ai-knowledge | `roguemap-core` | 知识图谱 KV 存储 (节点/边) |
| shiyu-ai-memory | `roguemap-memory` | AI 记忆层 (BM25 + 可选向量) |

- `roguemap-memory` 自动传递 `roguemap-embedding`（含 `UniversalEmbeddingProvider`），无需单独引入
- `roguemap-core` 仅用于`RogueMap<String, String>` 堆外 KV 场景，与 RogueMemory 互不依赖
- 各模块按需引入，不重复

### 5.1 检索模式选择

| 模式 | 需要 Embedding API | 适用场景 |
| --- | --- | --- |
| `KEYWORD_ONLY` (默认) | ❌ 不需要 | 开发/测试环境，离线可用 |
| `HYBRID` | ✅ 需要 | 生产环境，语义理解 + 关键词精确召回 |
| `VECTOR_ONLY` | ✅ 需要 | 纯语义相似度检索 |

## 6. 关键决策记录

| 决策 | 方案 | 理由 |
| --- | --- | --- |
| model 顶层依赖 | model 不依赖任何业务模块 | 避免循环依赖 |
| BO 放各业务模块 | BO 只在所属模块中定义 | 高内聚，低耦合 |
| 跨模块共用 BO 放 model | AiModelBO, ConversationMessageBO 等 | 被多个模块引用 |
| Repository 放业务模块 | 替换老的大 dal 设计 | Repository 本质是业务逻辑 |
| DO 放 dal | 全模块共用数据定义 | 所有模块都依赖 dal |
| @AutoMapper 策略 | BO↔DO 双向转换 | BO 在业务模块则注解在 BO 上 |
| Sa-Token SSO 方案 | 使用 Sa-Token SSO，中心会话 + SSO Client 端通过 URL 重定向 | 避免共享 Token/Secrect |

# 项目改造方案

## 1. 当前状态分析

### 1.1 模块结构

```
shiyu-ai (根 pom)
├── shiyu-common (聚合模块)
│   ├── shiyu-common-bom        依赖版本管理
│   ├── shiyu-common-core       核心工具 (Result/Login/BizException/Validate)
│   ├── shiyu-common-excel      Excel 导入导出
│   ├── shiyu-common-mybatis    MyBatis-Flex 封装 (BaseMapper/TenantEntity)
│   ├── shiyu-common-thread     线程池封装 (虚拟线程/Otel上下文)
│   └── shiyu-common-web        Web 配置 (OpenAPI/XSS/Filter)
│
└── shiyu-agent (100+ Java 文件，单体模块)
    ├── biz/agent/              Agent 核心 (LangGraph4j/LLM/RAG/Memory/Tool)
    ├── biz/auth/               认证授权 (Sa-Token 多租户)
    ├── biz/common/             通用字典/文件/时区
    ├── biz/record/             学习记录 (Profile/Record/Media/Tag/Timeline)
    ├── config/                 启动配置 (SaToken/TenantFlex/DB初始化)
    ├── dal/                    数据访问 (DataObject/Mapper/DataSource)
    ├── domain/                 BO/Request/VO (跨 biz 共用)
    ├── langchain4j/            模型适配 (Lc4jModelManager/PlatformAdapter)
    └── langgraph4j/            图引擎 (Graph/BaseNode/各节点类型)
```

### 1.2 当前代码统计

| 维度       | 当前状态                    |
| ---------- | --------------------------- |
| 运行模块数 | 2 (shiyu-common + shiyu-agent) |
| Java 文件  | ~160 (agent 模块内)         |
| 业务领域   | Agent + Auth + Record       |
| AI 能力    | LangChain4j 5 平台适配 + LangGraph4j 12 种节点 |
| 数据源     | H2 (开发) + 5 个 SQL 初始化脚本 |
| 工作流     | LiteFlow 已声明依赖但未使用 |
| MCP        | application-mcp.yml 已配置但未接入 |

### 1.3 关键接口清单

| 接口 | 文件 | 方法数 |
| --- | --- | --- |
| Lc4jService | `biz/agent/service/Lc4jService.java` | 4 (call/stream/getChatModel/...) |
| MemoryService | `biz/agent/service/MemoryService.java` | 6 (save/retrieve短期长期记忆) |
| RagService | `biz/agent/service/RagService.java` | 2 (retrieve + 默认版) |
| ToolService | `biz/agent/service/ToolService.java` | 1 (execute) |
| AgentService | `biz/agent/service/AgentService.java` | 5 (register/execute/switch) |

### 1.4 当前问题

- shiyu-agent 是"大单体"：AI 核心、业务逻辑、数据访问、认证授权混杂在一起
- 无法将 Knowledge、Education 等业务域作为独立模块
- 知识图谱、学习引擎、能力模型、艾宾浩斯复习 等无处安放
- LiteFlow/MCP 已声明依赖，但没有对应模块承载
- RogueMap(嵌入式 KV)/向量存储/全文搜索 未引入

## 3. 改造阶段

### Phase 1 — 模块拆分（结构不动逻辑，仅重组 Maven 边界）

**目标**：将 shiyu-agent 拆为 6 个新模块 + 保留精简后的 shiyu-agent 作为启动模块。

**不动业务逻辑，只做"搬家"**。

#### 3.1 新建模块清单

| 模块 | 承载职责 | 包前缀 |
| --- | --- | --- |
| `shiyu-ai-core` | Lc4jService + Lc4jModelManager + PlatformAdapter | `com.shiyu.ai.core` |
| `shiyu-ai-model` | Lc4jRequest/Lc4jResponse/AgentDefinition/AgentVersion 等共用 BO | `com.shiyu.ai.model` |
| `shiyu-ai-agent` | Graph 引擎 + BaseNode + 12 种 Node + AgentService | `com.shiyu.ai.aiagent` |
| `shiyu-ai-memory` | MemoryService + LongTermMemoryRepository | `com.shiyu.ai.memory` |
| `shiyu-ai-rag` | RagService + 文档检索 | `com.shiyu.ai.rag` |
| `shiyu-ai-mcp` | ToolService + MCP 工具接入 | `com.shiyu.ai.mcp` |

#### 3.2 保留在 shiyu-agent 的内容

| 包 | 内容 | 说明 |
| --- | --- | --- |
| `biz/auth/` | AuthController/Service + SaToken 配置 | 认证授权留在启动模块 |
| `biz/common/` | DictController/FileController/TimezoneController | 通用管理 |
| `biz/record/` | Profile/Record/Media/Tag/Timeline | 学习记录业务 |
| `config/` | ApplicationStartupListener/DB 初始化 | 启动配置 |
| `dal/` | 全部 Mapper + DataObject + 多数据源 | 数据访问层 |
| `domain/` | BO/Request/VO | 与 shiyu-ai-model 共存（后期迁移） |
| `handler/` | SaTokenExceptionHandler | 全局异常 |
| `interceptor/` | UserContextInterceptor | 用户上下文 |
| `utils/` | SaTokenHelper | 工具类 |

### Phase 2 — 知识引擎（核心基础设施）

新建 `shiyu-ai-knowledge` 模块，实现：

- **知识图谱 (DAG)**：`GraphStore` 接口 + `InMemoryGraphStore`（后续可替换为 RogueMap）
- **图算法**：DFS / BFS / 拓扑排序 / 前置知识检测
- **学习能力模型**：Bloom Taxonomy 六维度能力值
- **遗忘曲线**：复习任务生成 + 衰减函数
- **知识实体**：Knowledge / Relation / Subject / Textbook / Chapter

### Phase 3 — 教育业务域

新建 `shiyu-ai-education` 模块，实现：

- **学段/学科/教材/章节**：多版本教材映射
- **课程**：课程+章节+知识关联
- **题库**：题目 CRUD + 智能出题（AI 生成）
- **考试**：手动/AI 组卷 + 答题 + 评分
- **复习**：艾宾浩斯 1/3/7/15/30/90 天任务
- **学习计划**：按日期 + 知识路径自动排期
- **学习分析**：概览 / 能力雷达图 / 薄弱点 / 趋势
- **成长档案**：成就系统 + 周报

### Phase 4 — 教育 Agent + LiteFlow + MCP

- 在 `shiyu-ai-agent` 内新增教育 Agent（TeacherAgent / PracticeAgent / ExamAgent / ReviewAgent / PlannerAgent / ReportAgent）
- 在 `shiyu-ai-workflow` 定义 LiteFlow Chain（learning / review / exam / recommend / tutor / ability）
- 在 `shiyu-ai-mcp` 接入 MCP 工具（搜索知识点 / 出题 / OCR / TTS / ASR）

### Phase 5 — 存储升级（可选）

- 引入 RogueMap 替换 InMemoryGraphStore
- 向量存储：RogueMap Embedding 模块
- 全文检索：RogueMap 倒排索引
- 缓存：RogueMap LRU+TTL 替换 Caffeine

```

              ↓
```

## 5. Phase 1 风险控制

| 风险 | 缓解措施 |
| --- | --- |
| 包名改动大，IDE 批量替换易错 | 使用 IDEA 的 `Refactor → Move Package`，保留原 git history |
| 跨模块循环依赖 | shiyu-ai-model 必须纯 POJO，不包含 Spring @Service |
| Mapper XML 路径失效 | `application.yml` 的 mapper-locations 保持 `classpath*:mapper/*.xml` |
| Flyway 找不到新表 | `databaseInitializer` 中 SQL 脚本路径保持相对 |
| LangGraph4j Node 无法注入 | shiyu-ai-agent 的 package 需要在 `@ComponentScan` 中 |

## 6. Phase 2 执行要点（预告）

**Phase 1 完成后启动 Phase 2**，核心任务：

1. **新建 `shiyu-ai-knowledge` 模块**
2. 实现 `GraphStore` 接口（先用 `ConcurrentHashMap` + JSON，无需引入 RogueMap）
3. 实现 `KnowledgeService`（知识点 CRUD）+ `KnowledgeRelationService`（关系 CRUD）
4. 实现 `LearningPathService`（DFS + 拓扑排序 + 前置知识缺失检测）
5. 实现 `AbilityService`（Bloom Taxonomy 六维度能力值更新）
6. 新增 `db/migration/knowledge__init.sql`（knowledge 表 + knowledge_relation 表）
7. Phase 3 再接知识图谱可视化、向量检索、能力评估等高阶功能

# 错误码手册

本文以 `BizResultCode`、全局异常处理器和 Sa-Token 处理器为准。业务接口通常返回统一 JSON，而不是只依赖 HTTP 状态码，调用方应同时检查 `success` 与 `code`。

```json
{
  "code": 200,
  "data": {},
  "message": "成功",
  "error": null,
  "success": true
}
```

## 通用错误码

| code | 含义 | 前端处理建议 |
| ---: | --- | --- |
| 200 | 成功 | 使用 `data` |
| 400 | 请求失败 | 展示服务端信息并检查请求格式 |
| 401 | 未登录、令牌失效或旧令牌已被轮换 | 清理会话并跳转登录页 |
| 403 | 已登录但无权限，或跨域来源被拒绝 | 展示无权限；不要自动重试 |
| 404 | 资源不存在 | 返回列表或展示空状态 |
| 408 | 请求超时 | 对幂等查询提供人工重试 |
| 500 | 系统内部错误 | 记录 trace、时间和接口，不向用户泄露堆栈 |

## 业务错误码

| code | 默认含义 | 常见场景 |
| ---: | --- | --- |
| 10001 | 用户已存在 | 注册或创建重复账号 |
| 10002 | 用户名或密码错误 | 密码登录失败 |
| 10003 | 验证码错误 | 验证码登录或校验失败 |
| 10004 | 密码验证失败 | 敏感操作二次验证失败 |
| 10005 | 角色不存在 | 角色分配目标无效 |
| 10006 | 参数绑定失败 | JSON 字段缺失、类型错误；例如刷新接口缺少 `accessToken` |
| 10007 | 参数校验失败 | `@Valid` 规则不满足 |
| 10008 | 参数执行异常 | 参数解析后的执行异常 |
| 10009 | 业务异常 | 领域校验、状态冲突等，优先展示服务端 `message` |
| 11003 | 无权限，请联系管理员申请权限 | 权限码不足 |
| 11004 | 越权操作 | 跨租户或超出数据范围 |
| 11005 | 角色不存在或已禁用 | 当前租户角色失效 |
| 11006 | 非法操作 | 状态机或安全规则拒绝 |
| 30001 | 预览环境不支持此操作 | 演示/预览环境写操作 |

## 特殊响应

- SSE 接口返回 `text/event-stream`，错误可能作为事件或连接中断出现，不能按普通 JSON 一次性解析。
- 文件下载返回二进制 `ResponseEntity`；404/403 可能是 HTTP 错误而非统一 `Result`。
- CORS 预检被拒绝时直接返回 HTTP 403，浏览器不会把业务 JSON 暴露给前端。
- `/auth/refresh` 请求体字段是 `accessToken`；成功时 `data` 本身是新的 token 字符串，并立即使旧 token 失效。

## 排障顺序

1. 记录请求方法、路径、HTTP 状态、`code`、`message` 和发生时间。
2. 401 检查 `Authorization: Bearer <token>`、有效期和是否刚完成轮换。
3. 403 对照《菜单、角色与权限矩阵》，同时确认当前租户。
4. 10006/10007 对照 OpenAPI schema，确认字段名、Content-Type 与必填项。
5. 10009 查看领域日志和对象当前状态；不得依赖字符串解析决定业务分支。

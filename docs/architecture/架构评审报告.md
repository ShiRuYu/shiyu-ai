## 一、整体模块设计

### 现状（✅ 优秀，9.5/10）

当前项目包含 **15 个有效构建模块**（`shiyu-common` 聚合 5 个子模块；根 POM modules 见下），与评审建议的领域边界高度吻合：

| 实际模块 | 评审建议 | 匹配度 |
|---------|---------|:------:|
| shiyu-ai-agent | shiyu-agent | ✅ 平台核心 |
| shiyu-ai-knowledge | shiyu-knowledge | ✅ |
| shiyu-ai-model | shiyu-ai-model | ✅ |
| shiyu-ai-memory | shiyu-memory | ✅ |
| shiyu-ai-dal | — | ✅ 实现层 |
| shiyu-ai-vector | — | ✅ 向量存储 |
| shiyu-ai-tool | — | ✅ 工具模块 |
| shiyu-ai-bootstrap | shiyu-server | ✅ |
| shiyu-common/* | shiyu-common | ✅ core/web/thread/storage/mybatis |

**根 Maven reactor（15 模块）**：

```
shiyu-common → shiyu-ai-vector → shiyu-ai-model → shiyu-ai-memory → shiyu-ai-tool
→ shiyu-ai-knowledge → shiyu-ai-agent → shiyu-ai-usage → shiyu-ai-plugin
→ shiyu-ai-auth → shiyu-ai-record → shiyu-ai-education → shiyu-ai-dal
→ shiyu-ai-web → shiyu-ai-bootstrap
```

**技术栈**：Spring Boot 4.1.0 + Java 21（虚拟线程），非常现代。

### 2026-08-04 相对上轮评审的改进 ✅

| 改进项 | 说明 |
|--------|------|
| 模块边界强制 | 新增 `LayerBoundaryArchTest`（分层边界 ArchUnit 测试） |

| 依赖收敛 | 移除 LiteFlow（`shiyu-ai-workflow`），编排统一 Agent 引擎 |

## 七、Memory 独立性

### 现状（✅ 已完全独立）

shiyu-ai-memory 是独立的顶级模块，不依赖 shiyu-ai-agent 或 shiyu-ai-chat：

```
MemoryService (编排层)
    ↓
MemoryStore SPI (存储抽象)
    ├── Memory (SPI 模型)
    ├── MemoryQuery (查询对象)
    └── MemoryType (枚举：SHORT_TERM / LONG_TERM / WORKING)
    ↓
port/repository（2026-08-04 新增接口）
    ├── ConversationMessageRepository
    ├── EpisodicMemoryRepository
    └── LongTermMemoryRepository
    ↓
DAL (shiyu-ai-dal/memory) 实现
```

**关键能力**：
- 短时记忆（对话历史管理）
- 长时记忆（语义记忆存储与检索，重要性衰减）
- 情景记忆（EpisodicMemory）
- 混合召回策略（HybridRecallStrategy）
- 记忆压缩（滑动窗口 SlidingWindowCompressor）
- 记忆巩固（ConsolidationPipeline）
- 会话摘要（LLM 生成 + 截断回退）

## 八、Knowledge Repository

### 现状（✅ 已实现，且 2026-08-04 完成 DDD 升级）

**重构前**：`shiyu-ai-dal/knowledge/` 集中管理 BO/DO/Mapper/Repository。

**重构后（2026-08-04）**：

```
shiyu-ai-knowledge/
├── domain/model/            BO（11 个：KnowledgeDocument/DocumentRelation/DocumentVersion/
│                            Chunk/Relation/Space/SpaceMember/DifficultyScale/ReviewRecord…）
├── port/repository/         仓储接口（8 个）
└── retrieval/ 等            领域服务

shiyu-ai-dal/knowledge/      实现层（DO/Mapper/Repository 实现）
```

**Repository 标准模式**：

```java
@Component
public class KnowledgeChunkRepository {   // dal 实现
    @Resource
    private KnowledgeChunkMapper mapper;

    public void insert(KnowledgeChunkBO bo) {
        KnowledgeChunkDO entity = MapstructUtils.convert(bo, KnowledgeChunkDO.class);
        mapper.insertSelective(entity);
        bo.setId(entity.getId());
    }

    public List<KnowledgeChunkBO> selectByKnowledgeId(Long knowledgeId) {
        QueryWrapper qw = new QueryWrapper();
        qw.eq(KnowledgeChunkDO::getKnowledgeId, knowledgeId);
        return MapstructUtils.convert(mapper.selectListByQuery(qw), KnowledgeChunkBO.class);
    }
}
```

## 九、Agent 生命周期

### 现状（⚠️ 基础完整，待丰富）

**Agent 部署生命周期**（AgentState）：
```
CREATED → DEPLOYED → DISABLED → ARCHIVED
```

**Execution 执行生命周期**（ExecutionStatus，2026-08-04 现状）：
```
PENDING → RUNNING → COMPLETED
                   → FAILED
                   → PAUSED → RUNNING
                   → CANCELLED
```

```java
public enum ExecutionStatus {
    PENDING, RUNNING, PAUSED, COMPLETED, FAILED, CANCELLED
}
```

### 差距

**缺少精细中间状态**（QUEUED / WAITING_TOOL / WAITING_USER / WAITING_MODEL / CANCELLING）。当前 6 状态满足主流程；异步等待类场景待后续按需补充。

## 十、事件驱动

### 现状（✅ 基础具备，异步化待统一）

**已有事件体系**：

| 事件类 | 触发时机 | 状态 |
|--------|---------|:----:|
| AgentExecutionStartedEvent | Agent 开始执行 | ✅ |
| AgentExecutionCompletedEvent | Agent 执行完成 | ✅ |
| AgentExecutionFailedEvent | Agent 执行失败 | ✅ |
| NodeExecutionStartedEvent | 节点开始执行 | ✅ |
| NodeExecutionCompletedEvent | 节点执行完成 | ✅ |
| ModelCallEvent | 模型调用 | ✅ |
| AuditEvent | 审计日志 | ✅ |
| DomainEvent (基类) | 领域事件基类 | ✅ |

### 问题

1. **同步阻塞**：Spring 默认 ApplicationEventPublisher 是同步的
2. **事件粒度不足**：缺少 PromptBuilt/KnowledgeRetrieved/MemoryRetrieved/ToolCalling/ModelStreaming/TokenUsage 细粒度事件

### 建议

- 异步化：`SimpleApplicationEventMulticaster` + common-thread 线程池
- 补充事件：TokenUsageEvent（供 usage 统计）、ModelStreamingEvent（供 SSE 推送）等

## 十五、统一 Runtime

### 现状（✅ 架构决策变更：不新增 runtime 模块）

**2026-08-02 评审**：建议抽取 `shiyu-ai-runtime` 模块 + Executor SPI（AgentExecutor/WorkflowExecutor/ChatExecutor/ComfyExecutor/EducationExecutor）。

**2026-08-04 决策**：

- **未创建** runtime 模块
- **移除 LiteFlow**：`agent/workflow/`、`shiyu-ai-workflow` 全部删除
- 流程编排统一由 Agent 引擎（LangGraph4j）承担：`AgentRuntime + AgentExecutor + Graph + BaseNode`
- 教育执行通过 education 模块的 Agent/节点 Creator 注册进引擎 —— "平台引擎 + 业务执行器插件化"

**结论**：原"多执行器 Runtime"规划已被"Agent 引擎统一编排 + 业务节点插件化"取代，功能等价且更简洁，**无需再建 runtime 模块**。

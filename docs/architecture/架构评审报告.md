## 九、Agent 生命周期

### 现状（⚠️ 基础完整，待丰富）

**Agent 部署生命周期**（AgentState）：
`
CREATED → DEPLOYED → DISABLED → ARCHIVED
`

**Execution 执行生命周期**（ExecutionStatus）：
`
PENDING → RUNNING → COMPLETED
                   → FAILED
                   → PAUSED → RUNNING
                   → CANCELLED
`

**状态机验证**（AgentStateMachine）：
``java
TRANSITIONS.put(PENDING, Set.of(RUNNING, CANCELLED));
TRANSITIONS.put(RUNNING, Set.of(COMPLETED, FAILED, PAUSED, CANCELLED));
TRANSITIONS.put(PAUSED, Set.of(RUNNING, CANCELLED));
TRANSITIONS.put(COMPLETED, Set.of());   // 终态
TRANSITIONS.put(FAILED, Set.of());      // 终态
TRANSITIONS.put(CANCELLED, Set.of());   // 终态
``

### 差距

**缺少精细中间状态**：
- WAITING_TOOL — 等待工具调用完成（异步工具场景）
- WAITING_USER — 等待用户输入（多轮交互）
- WAITING_MODEL — 等待模型响应
- QUEUED — 排队等待执行
- CANCELLING — 取消中（优雅关闭）

**建议补充**：

`
PENDING → QUEUED → RUNNING → WAITING_MODEL → WAITING_TOOL → WAITING_USER → RUNNING [...]
                                                              → PAUSED → RUNNING
         → CANCELLING → CANCELLED
         → COMPLETED / FAILED
`

| 事件类 | 触发时机 |
|--------|---------|

@Bean
public ApplicationEventMulticaster applicationEventMulticaster(ThreadPoolTaskExecutor executor) {
    SimpleApplicationEventMulticaster multicaster = new SimpleApplicationEventMulticaster();
    multicaster.setTaskExecutor(executor); // 异步执行
    return multicaster;
}
``

## 十一、统一 Context

### 现状（❌ 缺失）

当前各处使用 **Map<String, Object>** 传递参数：

``java
// Controller 自行拼接

Execution 类字段也较简单：
- agentId, version, status, input, output, errorMessage
- userId, sessionId, startTime, endTime, durationMs
- nodeExecutions, lastCheckpointId

``java
public class ExecutionContext {

    private String requestId;

    private Long userId;
    private String userRole;
    private String scopedTenantId;

    // 会话
    private String conversationId;
    private String sessionId;

    // 执行目标
    private String agentId;
    private String agentVersion;
    private String workflowId;

    // 执行配置
    private AgentExecutionConfig config;

    // 流程变量
    private Map<String, Object> variables;

    // AI 相关
    private List<Message> messages;                  // 对话历史
    private List<Memory> retrievedMemory;             // 已检索记忆
    private List<KnowledgeChunk> retrievedKnowledge;  // 已检索知识
    private List<ToolCall> toolCalls;                 // 工具调用记录
    private String builtPrompt;                       // 已构建的 Prompt

    // 执行统计
    private TokenUsage tokenUsage;
    private CostTracker costTracker;
    private int retryCount;

    // 控制
    private Duration timeout;
    private CancellationToken cancellationToken;

    // 扩展
    private Map<String, Object> metadata;
}
``

**影响**：统一后所有模块只传 ExecutionContext，不再传十多个参数。

## 十二、Pipeline 模式

### 现状（❌ 缺失）

当前基于 LangGraph4j 的 Graph 引擎，节点间通过 DAG 编排。但缺少一层 **Pipeline** 抽象来专门处理 Prompt 组装流程。

**Graph 当前模式**（节点内部自行处理 Prompt）：

`
输入 → Graph.compile() → invoke(input)
    → NodeA.process()    // NodeA 内部自建 Prompt → 调模型 → 返回结果
    → NodeB.process()    // NodeB 内部自建 Prompt → 调模型 → 返回结果
    → NodeC.process()    // NodeC 也自建 Prompt
`

**缺少统一 Prompt 组装流水线**：

`
Pipeline
├── SystemPromptStep        (系统提示词)
├── RolePromptStep          (角色提示词)
├── MemoryStep              (记忆注入)
├── KnowledgeStep           (知识注入)
├── HistoryStep             (历史对话)
├── ToolStep                (工具描述)
├── UserStep                (用户输入)
└── ModelStep               (模型调用)
`

### 建议方案

``java
public interface PipelineStep {
    String name();
    void execute(PipelineContext context);
}

public class PromptPipeline {
    private List<PipelineStep> steps;

    public PipelineResult execute(PipelineInput input) {
        PipelineContext ctx = new PipelineContext(input);
        for (PipelineStep step : steps) {
            step.execute(ctx);
        }
        return ctx.buildResult();
    }
}
``

- 共享的调度器（Scheduler）

│   └── EducationExecutor
├── scheduler/            调度器
├── registry/             ExecutorRegistry 注册中心

├── event/                统一事件体系
├── metrics/              执行指标
├── cancellation/         取消机制
├── checkpoint/           检查点（通用化）
├── retry/                重试策略
├── streaming/            流式处理

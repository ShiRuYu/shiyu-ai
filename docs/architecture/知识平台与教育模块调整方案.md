# 知识平台与教育模块调整方案

> **状态更新（2026-08-04）**：本方案已按既定方向落地（对应 commit `33a2712`~`7cea6b9`）。
> 各节标注：✅ 已落地 / ⚠️ 部分 / 🔜 待办（前端仓库）

## 1. 文档目的

本文档根据当前项目对 `knowledge` 模块和 `education` 模块的分析，明确领域边界、目标架构、接口方向和迁移步骤。

配套执行计划：

[知识平台迁移执行计划.md](./知识平台迁移执行计划.md)

本次调整的核心目标：

1. 将 `knowledge` 建设为企业级通用知识平台，而不是仅面向教育的知识点模块。
2. 将旧版"知识点管理系统"能力合并到新版知识引擎。
3. 让 `education` 依赖 `knowledge`，只维护教育业务对知识的使用方式。
4. 消除旧版接口、新版 V2 接口、两套文档处理流程和两套索引体系并存的问题。

## 2. 当前问题概述（现状核对）

原方案指出 `knowledge` 模块同时承载旧版教育知识点体系与企业知识引擎两套职责。

**2026-08-04 现状**：✅ 两套体系已合并收敛，当前 `knowledge` 只保留企业知识引擎（新版）：

- 旧版教育知识点体系（`/knowledge/knowledge/**`、`/knowledge/document/**`）已删除
- 新版企业知识引擎（知识空间/文档版本/审核发布/异步摄取/混合检索/审计评测）为唯一实现
- 旧模块 `shiyu-ai-rag`（RagService/RagOrchestrator/LlmReranker）与 `shiyu-ai-workflow`（LiteFlow）已删除
- 前端旧页面（前端仓库）仍待迁移 🔜

## 3. 目标定位

将 `knowledge` 定位为：

> 企业级通用知识平台（Unified Knowledge Platform）

它负责"知识内容本身"和知识内容的生命周期、组织、检索，不限定于教育场景。

## 10. 迁移实施阶段（状态核对）

### 阶段一：确定新版为唯一主模型 ✅ 已完成

- `/knowledge/**` 为唯一正式接口
- `KnowledgeSpace` 为顶层边界
- 所有接口带 `spaceId` 和租户隔离

### 阶段二：合并旧版知识点能力 ✅ 已完成

- `KnowledgeService` → `KnowledgePointService` + `KnowledgeSpaceService`
- `KnowledgeRelationService` 空间化
- `KnowledgeGraph` 持久化、空间隔离
- `LearningPathService` → `KnowledgePathService`
- 知识点-文档关系由 knowledge 统一维护

### 阶段三：统一文档摄取流程 ✅ 已完成

统一为：

```text
上传 → 版本 → 异步摄取任务 → 文档解析 → Chunk → Embedding → 审核 → 发布 → 空间索引
```

旧版同步调用已废弃：

```java
// 已删除
DocumentKnowledgeService.create(...)
ingestionService.ingest(...)
```

### 阶段四：education 改为依赖 knowledge ✅ 已完成

- education 不再依赖 knowledge DAL
- education 通过 knowledge Service 查询知识点和文档
- 教育 Agent/节点已迁入 education 模块

### 阶段五：前端收敛 🔜 前端仓库

前端新版页面拆分（知识空间/知识点/文档中心/知识图谱/检索测试/摄取任务/索引管理/审计运维）在独立前端仓库推进。

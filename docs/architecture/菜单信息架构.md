# 菜单信息架构与数据契约

> 当前基线版本：`2`
> 更新日期：2026-08-09

## 1. 导航边界

前端使用 Vben `mixed` 权限模式。工作台由前端核心路由提供，后端负责其余业务菜单，因此最终一级导航为：

1. 工作台（前端）
2. Agent 平台（菜单 ID `10`）
3. 知识引擎（菜单 ID `70`）
4. 教育空间（菜单 ID `1500`）
5. 日常记录（菜单 ID `80`）
6. 系统管理（菜单 ID `1`）

文件管理（ID `90`）是系统管理子菜单，不再是一级入口。

## 2. 教育空间分组

教育空间直属可见节点只允许下列六个 `CATALOG`：

| ID | code | 标题 | 默认页面 |

| 1600 | `EduLearning` | 学习 | `/learning/course` |
| 1610 | `EduPracticeExam` | 练习与考试 | `/practice/question` |

| 1640 | `EduLearningAnalytics` | 学习分析 | `/analytics-center/report` |

- 练习与考试：`1510`、`1511`、`1520`、`1521`，以及隐藏执行路由 `1564`–`1566`；
- 复习：`1530`、`1531`；
- AI 辅学：`1540`–`1544`；
- 学习分析：`1550`–`1553`；

## 3. 权限契约

后端返回用户菜单时只会对查询结果建树，不会自动补祖先。因此授权必须同时包含页面及全部目录祖先。

- 超级管理员、管理员：拥有五个新增目录及教育配置。
- 普通用户：拥有五个学习侧目录，不拥有教育配置。
- 租户菜单授权必须包含新增目录。
- 新建自定义角色时，保存子页面权限的同时应保存祖先目录；管理端菜单树负责表达这种父子关系。

基线 1 升级脚本不会扩大页面权限。它仅在租户或角色已经拥有某组至少一个子页面时，为该租户或角色补充对应目录。

## 4. 数据库升级

`DatabaseInitializer` 仍以完整 H2 基线作为新库来源，但允许显式的参考数据迁移链：

```text
空数据库 ──安装──> 基线 2
基线 1   ──事务迁移 01──> 基线 2
其他版本 ──拒绝启动
```

迁移资源：

`infrastructure/shiyu-ai-dal/src/main/resources/db/migration/h2/01_menu_information_architecture.sql`

迁移在一个事务内执行。任何 SQL 失败都会回滚，`COMMON_SCHEMA_BASELINE` 只在迁移成功后更新为版本 `2`。

当前自动升级仅支持项目实际使用的 H2 基线。MySQL 生产化前必须提供等价迁移工具和脚本，不能直接复用 H2 SQL。

## 5. 菜单 API 契约

`RouteMenuVO` 输出字段规则：

- `name`：来自 `AUTH_MENU.CODE`，前端路由合并键，全局唯一；
- `path`：稳定业务 URL；目录路径不得与页面冲突；
- `type`：输出为小写 `catalog` / `menu`；
- `component`：目录留空，页面映射到前端 `src/views`；
- `redirect`：目录必须指向一个已授权的默认页面；
- `meta.title`、`meta.icon`、`meta.order`：来自菜单记录；
- `meta.hideInMenu`：`SHOW = FALSE` 时输出；
- `children`：支持三级及更深层级。

前端会在动态路由注册前校验节点结构、整树 `name` 唯一性和 `component` 文件是否存在。契约错误会进入可重试错误页，因此新增或移动页面时必须同步前端组件注册。

## 6. 验证

新库与升级契约由 `DatabaseInitializerTest` 验证，覆盖：

- 菜单总数、一级根节点数量；
- 教育空间六个直属目录；
- 每组页面与隐藏路由归属；
- 业务 URL 和组件路径保持不变；
- 租户与三种内置角色的目录授权；
- 基线 1 到基线 2 的事务升级。

运行命令：

```bash
mvn -pl infrastructure/shiyu-ai-dal -am \
  -Dtest=DatabaseInitializerTest \
  -Dsurefire.failIfNoSpecifiedTests=false test
```

前端对应文档位于 `shiyu-ui/docs/web-naive-layout-redesign.md`。

通用 API、权限上下文和 SSE 约定见 `docs/contracts/前端集成契约.md`。

# 知识平台迁移执行计划

> **状态更新（2026-08-04）**：本计划的后端部分已基本落地（对应 commit `33a2712`~`7cea6b9` 系列重构）。
> 各阶段任务标注：✅ 已完成（后端代码已落地） / ⚠️ 部分完成 / 🔜 待办（主要涉及前端仓库，本仓库为纯后端）

## 1. 执行目标

将当前旧版"知识点管理系统"和新版企业知识引擎逐步合并，最终形成唯一的 `knowledge` 知识平台：

```text
knowledge
├── 知识空间
├── 知识点
├── 知识关系与图谱
├── 知识路径
├── 文档与版本
├── 知识点-文档关系
├── Chunk / Embedding / Index
├── 检索与 RAG
└── 审核、任务、审计、备份
```

`education` 只依赖 `knowledge`，维护教育业务本身：

```text
课程、章节、题目、教材、资源、学习状态、复习、能力和计划
```

## 2. 执行原则

### 2.1 先迁移、后删除 ✅ 已遵循

旧逻辑（知识模块）已按"盘点依赖 → 新接口实现 → 兼容转发 → 调用方迁移 → 删除旧逻辑"完成收敛，`shiyu-ai-rag`、`shiyu-ai-workflow` 等遗留模块已删除。

### 2.2 不改变已有业务 ID ✅ 已遵循

现有教育数据引用 `knowledgeId` 保持不变，未破坏章节、题目、复习、能力等数据的关联。

### 2.3 不允许跨空间数据 ✅ 已落地

- 知识关系校验同空间创建（`KnowledgeRelationService`）
- 所有 Repository 带 `tenantId / spaceId` 条件
- 新增 `security/KnowledgeAccessContext` 空间访问控制
- Agent RAG 检索已接入"授权知识空间"（commit `6ff0ad4`）

### 2.4 每个阶段必须可回滚 ✅ 已落地

- Flyway 迁移（V001–V026）逐步推进，新表新字段增量添加
- 数据库 H2（开发）/ MySQL（生产）双支持

本仓库为后端单体，旧接口已随重构删除；外部客户端若受影响需按新 API 迁移。

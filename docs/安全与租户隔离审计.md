# 安全与租户隔离审计

审计基于 2026-08-12 当前源码、H2 基线和独立运行实例，覆盖认证、权限、租户、文件、跨域、数据与运维入口。结论是：核心请求链路符合前后端逻辑，本轮修复了令牌轮换入口、CORS 过宽和文件写操作缺少权限注解三个问题；生产部署仍需按本文的加固清单配置。

## 请求安全链路

1. `SaServletFilter` 对除公开路径外的全部请求执行登录校验。
2. `UserContextInterceptor` 根据 token 加载用户、当前租户、角色和权限上下文。
3. `SaInterceptor` 执行 `@SaCheckPermission` 等方法级授权。
4. MyBatis-Flex 租户工厂向租户表查询追加租户条件。
5. 领域服务继续执行对象归属和状态校验。

前端的菜单隐藏只改善体验，不构成安全边界；最终授权始终以后端为准。

## 本轮已修复

| 项目 | 原问题 | 修复与验证 |
| --- | --- | --- |
| Token 轮换 | `/api/iam/auth/refresh` 被登录过滤器提前拦截，无法只凭请求体中的旧 token 轮换 | 将新路径加入两处公开清单，控制器自行验证 `accessToken`；独立实例验证新 token 有效、旧 token 401 |
| CORS | `allowCredentials=true` 同时允许任意来源模式 | 默认白名单限定 localhost/127.0.0.1 的 5888、5173，可用 `shiyu.web.cors.allowed-origin-patterns` 覆盖；允许来源 200、恶意来源预检 403 |
| 文件写操作 | 上传、删除只有登录和租户目录校验 | 分别增加 `file:upload`、`file:delete` 权限；原始基线已向 super/admin 角色分配这两个权限 |
| 编译边界 | JDK 25 构建时可能误用高于 Java 21 的 API | Maven 编译器改用 `release 21` |

## 租户隔离

- 数据库主要业务表通过租户字段和 MyBatis-Flex租户条件隔离。
- 文件 key 固定以 `tenant/{tenantId}/` 开头；列表按命名空间查询，下载和删除会验证前缀。
- 认证元数据中的部分表不走通用租户过滤，由认证仓储按 tenant/scope 显式查询。
- 线程池、定时任务、消息消费等脱离 HTTP 请求的代码必须显式设置并在 `finally` 清理用户/租户上下文；不得依赖上一个线程残留。
- 新建表时必须决定其是全局表还是租户表，并同时更新租户工厂白名单、数据字典与隔离测试。

## 公开与半公开路径

无需已有登录态：登录、注册、验证码登录、忘记密码、令牌轮换、验证码、OpenAPI/Swagger、H2 控制台、部分资源路径。注意：刷新接口虽然在登录过滤器中公开，但会在业务层验证旧 token，并非匿名获取 token。

生产建议：

- 关闭 Swagger/OpenAPI 或置于网关/VPN 后；H2 控制台必须关闭。
- 注册、忘记密码和验证码接口增加频率限制、失败计数与审计。
- 不要把 H2 文件、备份、日志、模型密钥目录暴露为静态资源。
- `education-resources` 的实际 URL 与 WebMvc 前缀应通过集成测试固定，避免公开清单和真实路由漂移。

## 密钥、模型与日志

- 模型/API 密钥只通过环境变量或密钥服务注入，不提交到仓库、前端构建物或文档示例。
- 日志不得记录 token、密码、验证码、完整模型密钥和敏感学习内容。
- 文件名、MIME 与大小均视为不可信输入；生产环境应增加恶意文件扫描与可执行内容隔离。
- S3/MinIO/OSS/COS 使用最小权限凭证，bucket 默认私有，下载优先短时签名 URL。

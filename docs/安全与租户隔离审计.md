# 安全与租户隔离审计

审计基于 2026-09-11 当前源码、H2/外部数据库基线和独立运行实例，覆盖认证、权限、租户、文件、跨域、数据库、Redis、事件与运维入口。结论是：核心请求链路符合前后端逻辑，基础设施 provider 已能独立切换；生产部署仍需按本文的加固清单配置。

## 请求安全链路

1. `SaServletFilter` 对除公开路径外的全部请求执行登录校验。
2. `UserContextInterceptor` 根据 token 加载用户、当前租户、角色和权限上下文。
3. `SaInterceptor` 执行 `@SaCheckPermission` 等方法级授权。
4. MyBatis-Flex 租户工厂向租户表查询追加租户条件。
5. 领域服务继续执行对象归属和状态校验。

前端的菜单隐藏只改善体验，不构成安全边界；最终授权始终以后端为准。

## 当前租户模型（2026-09-12 源码核查）

系统支持租户树，但每个业务请求只绑定一个当前租户。租户树用于管理范围和切换授权，不会让普通业务查询自动包含全部子租户数据。

| 概念 | 当前实现 |
| --- | --- |
| 归属租户 `homeTenantId` | 用户持久化上下文中的归属及委派授权根；缺失时部分流程从有效租户角色分配推导 |
| 当前租户 `currentTenantId` | 本次业务操作的数据作用域，转换成强类型 `TenantId` |
| 当前角色 `currentRole` | 当前租户内选中的角色；必须校验角色、分配和租户的有效状态 |
| 普通切换 `NORMAL` | 目标租户有效，用户拥有该租户的有效角色分配；优先保留适用角色，否则按角色 ID 选择 |
| 委派切换 `PARENT_SUPER_ADMIN` | 归属租户拥有有效超级管理员角色，可在允许的子树内进入没有直接角色分配的子租户，使用目标租户超级管理员角色 |

`AuthIdentityUseCase` 在父租户超级管理员已离开归属租户时，以当前租户作为继续下钻的子树根；允许返回归属租户，不允许直接横跳到该子树之外。目标有直接角色分配时使用普通切换模式。不能把任意管理员标志理解为跨租户数据过滤豁免。

切换成功前先写入用户 `ext_info` 的当前租户、归属租户、角色和切换模式；委派模式记录 `switchFromTenantId`，普通模式移除该字段。持久化失败返回失败；成功后清除用户上下文 Session 和路由菜单缓存。`UserContextInterceptor` 对缓存上下文继续校验运行期状态，失效时重新加载持久化选择，不永久信任旧 Session。选择保存在用户记录上，不应向调用者承诺不同设备之间的切换完全独立。

租户管理服务限制普通管理范围为当前租户子树，并防止非法父节点调整；删除时拒绝删除 ID 为 1 的租户及当前租户。服务中存在 `platformAdmin && homeTenantId == null` 的全局管理分支，但 HTTP 上下文是否能进入该分支需沿认证入口判断，不能仅凭此条件推断普通管理员可访问全平台。

## 租户隔离

- 数据库主要业务表通过租户字段和 MyBatis-Flex租户条件隔离。
- 文件 key 固定以 `tenant/{tenantId}/` 开头；列表按命名空间查询，下载和删除会验证前缀。
- `ContextTenantFactory` 始终通过 `TenantScope.require()` 返回唯一租户；缺少上下文会失败，没有按表名返回空租户的白名单。未配置租户列的全局表不依赖该过滤器；认证查找、租户树和部分角色管理仓储显式使用 `TenantManager.withoutTenantCondition`，必须结合调用方授权与显式查询条件逐项审查，不能把所有认证表统称为安全豁免。
- 线程池、定时任务、消息消费等脱离 HTTP 请求的代码必须显式设置并在 `finally` 清理用户/租户上下文；不得依赖上一个线程残留。
- 新建表时必须决定其是全局表还是租户表，配置租户列及显式授权条件，同步数据字典与隔离测试；禁止增加缺失上下文时放行的隐式回退。

请求中由服务端认证结果构建 `ActorContext` 并绑定 `TenantScope`，MyBatis 对受管理的租户列追加过滤，领域服务继续验证对象归属和操作权限。`ActorContext.requireTenant` 要求租户相等；自定义 SQL、JDBC、索引及对象存储不能假定自动享有 MyBatis 的过滤效果。客户端提交的目标租户只能作为切换或管理请求参数，不能直接成为可信业务上下文。

HTTP 请求结束及上下文加载失败时清理线程上下文。`TenantScope.withTenant` 在 `finally` 恢复原租户。线程任务装饰器恢复的是独立的 `TaskContext` 快照，并在结束时恢复工作线程原快照；这不等同于自动绑定 `TenantScope` 或 `UserContextHolder`。新增异步、调度和消费链路必须显式传递所需上下文并测试清理，不能仅因使用线程装饰器就认定租户上下文已传播。

## 租户默认数据初始化

IAM 的注册、租户创建及相关切换入口通过 `KnowledgeTenantProvisioning` 契约调用知识模块。知识实现按目标租户和默认空间编码查找，已存在则返回，否则创建“企业通用知识空间”，使用通用领域、`TENANT` 访问模式和 `DIRECT` 审核模式。它初始化的是知识空间，不是教育课程、学生或全部平台数据。

当前实现采用事务内先查后建；这不能单独证明并发初始化幂等，仍需结合数据库唯一约束和重复冲突处理验证。初始化是否与入口操作整体原子提交应按各入口事务边界确认，不将其描述为跨模块分布式事务。

本节为源码核查结论；文首历史运行审计不代表本次重新执行了全部部署或多设备联调。待完善项包括逐条核查手写查询、并发初始化及真实异步请求结束后的上下文生命周期。

## 公开与半公开路径

无需已有登录态：登录、注册、验证码登录、忘记密码、令牌轮换、验证码、OpenAPI/Swagger、H2 控制台、部分资源路径。注意：刷新接口虽然在登录过滤器中公开，但会在业务层验证旧 token，并非匿名获取 token。

生产建议：

- 关闭 Swagger/OpenAPI 或置于网关/VPN 后；H2 控制台必须关闭。
- 注册、忘记密码和验证码接口增加频率限制、失败计数与审计。
- 不要把 H2 文件、备份、日志、模型密钥目录暴露为静态资源。
- `education-resources` 的实际 URL 与 WebMvc 前缀应通过集成测试固定，避免公开清单和真实路由漂移。

## 密钥、模型与日志

- 模型/API 密钥只通过环境变量或密钥服务注入，不提交到仓库、前端构建物或文档示例。
- 日志不得记录 token、密码、验证码、完整模型密钥和敏感学习内容。
- 文件名、MIME 与大小均视为不可信输入；生产环境应增加恶意文件扫描与可执行内容隔离。
- S3/MinIO/OSS/COS 使用最小权限凭证，bucket 默认私有，下载优先短时签名 URL。
- PostgreSQL/MySQL 连接只从环境变量或密钥管理系统注入；应用启动校验 baseline 版本、种子和表集合，不以空库替换已有数据。
- Redis 只保存租约、限流、幂等键和短期缓存，不保存业务事实；生产连接失败时锁、限流和幂等快速失败，禁止静默回退到跨实例不一致的内存状态。
- Kafka 仅在显式 provider 下创建连接；outbox 消息限制重试次数并进入死信主题，消费端使用事件 inbox 主键去重，凭据和主题配置不得写入日志。

# ShiYu AI 后端项目介绍

> 面向新成员的快速说明；接口、字段和部署细节以参考文档与源码为准。

## 项目是什么

ShiYu AI 是以 Agent、Conversation、Knowledge 和 MAGMA Memory 为核心的多租户 AI 平台。平台能力与 Education 业务分开，通过 contract、事件和基础设施端口协作；Record 不在当前 Maven 构建中。

## 核心能力

| 能力 | 作用 |
| --- | --- |
| Agent / Runtime | 图编排、版本、执行、暂停恢复、工具审批和运行事件 |
| Conversation | 会话树、结构化消息、生成生命周期和 SSE |
| Model | OpenAI、DeepSeek、Ollama 等模型平台适配与路由 |
| Knowledge | 知识空间、文档、关系、RAG、评测和向量索引 |
| Memory | MAGMA 事件、实体、关系图和上下文召回 |
| IAM / Governance | 认证、租户、角色、权限、用量和审计 |
| Education | 课程、题库、考试、学生和学习计划等业务能力 |

## 模块边界

- `modules/applications`：启动入口、应用装配和公共 HTTP 接入。
- `modules/domains`：平台领域，每个领域拆为 `contract` 与 `implementation`。
- `modules/business/education`：独立业务边界，只依赖平台 contract，不反向依赖平台 implementation。
- `modules/infrastructure` 与 `modules/shared`：Web、MyBatis、存储、线程、向量和共享类型。

跨领域只通过 contract、事件或基础设施端口协作；Controller 不直接访问其他领域的 Repository。所有租户资源都必须带可信 `TenantId`，普通请求由认证上下文建立作用域。

## 本地默认行为

完整包和平台包都可以直接运行：默认使用 `dev`、9000 端口、本地 H2、local 文件存储和事务基础设施。生产环境通过环境变量或外部配置切换数据库、对象存储、向量、Redis 和事件 provider。

## 当前边界

- H2 是本地默认数据库；MySQL/PostgreSQL 需要先准备受控基线，应用启动只校验不迁移生产数据。
- 模型密钥、数据库密码和对象存储凭据不得提交到仓库。
- OpenAPI、数据字典和权限矩阵由脚本生成，不能手工维护统计数字。
- 前端和后端保留 `/api/{domain}` 路径；教育接口保留 `/api/education/**`。

# ShiYu AI 后端使用文档

> 面向本地开发、前后端联调、接口调用和部署维护。命令默认在 `shiyu-ai` 仓库根目录执行。

## 1. 环境准备

- JDK 21。
- Maven 3.8 或更高版本。
- 可选：Ollama 或任一兼容模型平台的 API Key。
- 前端联调时另需 Node.js 22.18/24.12 与 pnpm 11，详见前端使用文档。

确认环境：

```powershell
java -version
mvn -version
```

## 2. 第一次构建和启动

先从根目录构建整个 reactor：

```powershell
mvn clean test
mvn -pl infrastructure/shiyu-ai-bootstrap -am -DskipTests package
```

启动可执行 Jar：

```powershell
java -jar infrastructure/shiyu-ai-bootstrap/target/shiyu-ai-bootstrap-1.0.0.jar --spring.profiles.active=dev
```

默认地址：

| 服务 | 地址 |
| --- | --- |
| 后端 | `http://127.0.0.1:9000` |
| OpenAPI JSON | `http://127.0.0.1:9000/v3/api-docs` |
| Swagger UI | `http://127.0.0.1:9000/swagger-ui/index.html` |
| H2 Console | `http://127.0.0.1:9000/h2` |

Swagger UI 需要构建产物包含 `api-docs-ui` profile。它默认激活；如果命令显式使用了其他 Maven profile，应按需加回，例如 `-Pprod,api-docs-ui`。

不要直接进入 bootstrap 子目录后依赖本机 Maven 缓存运行旧模块。开发中修改任一模块后，从根目录重新构建最稳妥。

## 3. 数据目录

默认以项目根目录作为 `app.home`，运行数据写入 `data/`。部署时建议显式指定绝对目录：

```powershell
$env:APP_HOME='D:\shiyu-runtime'
java -jar infrastructure/shiyu-ai-bootstrap/target/shiyu-ai-bootstrap-1.0.0.jar --spring.profiles.active=dev
```

注意：

- 不要让两个进程共享同一 `APP_HOME`。
- 备份前应保证 H2、文件和向量索引处于一致状态，优先使用项目自身的备份机制。
- `data/` 是运行数据，不应提交到 Git。
- 需要重建本地环境时，先备份而不是直接删除数据目录。

## 4. 登录与账号

首次数据库基线包含用户名 `admin`，但仓库只保存密码哈希，不提供应公开传播的明文密码。请使用部署时约定的密码；无法确认时通过受控的密码重置流程处理。也可在允许注册的开发环境创建测试账号。

登录示例：

```powershell
$body = @{
  username = 'admin'
  password = '<your-password>'
} | ConvertTo-Json

$login = Invoke-RestMethod `
  -Method Post `
  -Uri 'http://127.0.0.1:9000/v1/auth/login' `
  -ContentType 'application/json' `
  -Body $body

$token = $login.data.accessToken
```

调用受保护接口：

```powershell
$headers = @{ Authorization = "Bearer $token" }
Invoke-RestMethod -Uri 'http://127.0.0.1:9000/v1/system/users/detail' -Headers $headers
Invoke-RestMethod -Uri 'http://127.0.0.1:9000/v1/system/menus/all' -Headers $headers
```

默认同一账号不允许并发会话。后一次登录可能使前一次登录的 Token 失效，自动化测试因此应串行使用种子管理员。

## 5. 配置模型平台

推荐登录 `shiyu-ui` 后在“Agent 平台”的平台管理和模型管理页面中维护平台，再在 Agent 或聊天调试中选择平台与模型。

本地开发也可创建未受版本控制的 `platform/shiyu-ai-model/src/main/resources/config/config.yml`（具体 classpath 位置可按启动方式调整），结构示例：

```yaml
shiyu:
  ai:
    ollama:
      base-url: http://127.0.0.1:11434
      api-key: ""
      model: gemma3:4b
    deepseek:
      base-url: https://api.deepseek.com
      api-key: ${AI_DEEPSEEK_API_KEY:}
      model: deepseek-v4-flash
```

不要把真实密钥提交到仓库。生产环境优先使用部署平台的秘密变量或外部配置中心。

使用本地嵌入模型时构建：

```powershell
mvn -Poffline-models,api-docs-ui -pl infrastructure/shiyu-ai-bootstrap -am -DskipTests package
```

未启用该 profile 时，必须由其他配置提供 `EmbeddingModel` Bean；两者都没有时，Embedding 调用会明确抛出“EmbeddingModel is not configured”异常，不存在可用的静默退化路径。知识向量能力上线前应实际验证嵌入模型和 512 维索引配置一致。

## 6. 与前端联调

后端保持端口 `9000`，前端开发服务器默认端口 `5888`。浏览器请求：

```text
http://127.0.0.1:5888/api/v1/auth/login
                         │
                         └─ Vite 移除 /api 并代理
                            http://127.0.0.1:9000/v1/auth/login
```

因此：

- 直接调用后端时使用 `/v1/auth/login`，不要加 `/api`。
- 通过前端或生产网关时使用 `/api/v1/auth/login`。
- 后端地址不同可在启动前端前设置 `VITE_PROXY_TARGET`。
- SSE 必须由代理保持流式传输，不能启用会缓存响应的中间层设置。后端另注册了 `/ws/usage`，但当前前端尚未消费该 WebSocket；接入前还需设计浏览器握手认证和网关转发方案。

## 7. 常用业务操作

### 7.1 创建并发布 Agent

1. 在平台管理中新增模型平台，验证地址、密钥和启用状态。
2. 在模型管理中新增模型并确保平台关联正确。
3. 在 Agent 管理中新建 Agent。
4. 新建或复制一个版本。
5. 在流程画布中添加节点和连线，并配置入口、模型、提示词、工具或知识空间。
6. 保存后执行图校验，修复无入口、断路、未知节点或缺少必填配置等问题。
7. 发布并激活版本，再注册/启用 Agent。
8. 使用聊天或执行调试页验证同步和流式输出。

### 7.2 建立知识空间

1. 创建知识空间并设置租户内访问模式。
2. 上传文档，等待解析与分块任务完成。
3. 检查文档版本、知识点和关系。
4. 构建或重建索引。
5. 在检索实验室验证关键词、向量和融合检索。
6. 用评测集检查召回质量，再将空间绑定到 Agent 的 RAG 节点。

### 7.3 配置权限

1. 创建或选择租户。
2. 建立角色并分配菜单与权限码。
3. 把用户关联到目标租户和角色。
4. 用户重新登录，或通过上下文切换刷新租户/角色。
5. 检查 `/v1/system/menus/all` 和 `/v1/auth/codes` 返回是否符合预期。

菜单的 `component` 必须与前端 `apps/web-naive/src/views` 下的组件路径对应，否则前端会进入“菜单加载失败”页。

## 8. 存储切换

本地存储无需额外配置。以 MinIO 为例：

```powershell
$env:SHIYU_STORAGE_TYPE='minio'
$env:SHIYU_STORAGE_MINIO_ENDPOINT='http://127.0.0.1:9001'
$env:SHIYU_STORAGE_MINIO_BUCKET='shiyu'
$env:SHIYU_STORAGE_MINIO_ACCESS_KEY='<access-key>'
$env:SHIYU_STORAGE_MINIO_SECRET_KEY='<secret-key>'

mvn -Pprod,s3 -pl infrastructure/shiyu-ai-bootstrap -am -DskipTests package
```

S3、Aliyun OSS、Tencent COS 使用同名的 `SHIYU_STORAGE_S3_*`、`SHIYU_STORAGE_OSS_*`、`SHIYU_STORAGE_COS_*` 环境变量。上线前验证上传、下载、删除、公开 URL 和大文件限制。

## 9. 打包

Windows：

```powershell
./scripts/package-cloud-windows.ps1
./scripts/package-offline-windows.ps1
```

Linux：

```bash
./scripts/package-cloud-linux.sh
./scripts/package-offline-linux.sh
```

脚本会构建 Jar，并生成预置 `data/db`、`data/files`、`data/index`、`data/models`、`data/backups` 目录的发行结构。对象存储、可观测性或 Swagger UI 有额外需求时，应按部署目标调整 Maven profile。

## 10. 测试与排错

完整测试：

```powershell
mvn test
```

常见问题：

| 现象 | 检查项 |
| --- | --- |
| 端口占用 | 查找占用 `9000` 的进程，或用 `--server.port=<port>` 临时改端口 |
| 数据目录被锁 | 是否已有实例使用同一 `APP_HOME`；不要绕过锁强行启动 |
| 前端请求 404 | 是否把 `/api` 直接发给了后端；检查 Vite/网关重写规则 |
| 401 或登录后立即失效 | Bearer 格式、账号是否被另一会话挤下线、Token 是否来自当前数据目录 |
| 菜单加载失败 | `/v1/system/menus/all` 的 name/path/component 是否唯一且对应前端组件 |
| Swagger UI 不存在 | 构建时是否显式使用了 profile 并遗漏 `api-docs-ui` |
| H2 基线失败 | 查看缺失表和基线标记；旧版本不会自动二次修改，应先备份并按完整最终基线重建 |
| 知识检索为空 | 文档任务状态、Embedding 是否可用、维度、空间/租户命名空间和索引版本 |
| SSE 无增量输出 | 代理是否缓冲响应、认证头是否透传、模型是否支持 streaming |
| 对象存储启动失败 | 是否启用 `s3` profile，以及 endpoint/bucket/凭据是否齐全 |

## 11. 生产检查清单

- 使用独立、受保护且有备份策略的 `APP_HOME`。
- 修改或重置种子管理员密码，不共享测试账号。
- 不在 Jar、Git、日志或前端环境变量中存储服务端密钥。
- 限制 H2 Console、Swagger UI 和管理端的外部可访问范围。
- 网关正确转发 `/api`、Authorization 和 SSE；启用 `/ws/usage` 前另行验证 WebSocket 握手认证与 upgrade。
- 验证租户隔离、角色权限、上传限制、备份恢复和保留策略。
- 在目标模型、目标数据量和目标向量索引上执行回归与容量测试。
- 生产数据库方案若不是 H2，先完成并验证对应的 schema、迁移与备份实现。

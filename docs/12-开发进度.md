## 进度功能分析

### 进度功能架构总览

系统中的"进度"涵盖 **5 个维度**，分布在 3 个模块中：

```
┌─────────────────────────────────────────────────────────────────┐
│                    进度功能架构                                    │
├──────────────┬──────────────────┬───────────────────────────────┤
│  维度         │  所属模块         │  持久化状态                    │
├──────────────┼──────────────────┼───────────────────────────────┤
│  学习状态进度  │  education       │  ⚠️ 纯内存 (ConcurrentHashMap) │
│  能力值进度    │  education       │  ✅ DB (ability_record 表)     │
│  复习进度      │  education       │  ✅ DB (edu_review_task 表)    │
│  学习计划进度  │  education       │  ✅ DB (edu_study_plan 表)     │
│  索引重建进度  │  knowledge       │  ⚠️ 纯内存 (ConcurrentHashMap) │
└──────────────┴──────────────────┴───────────────────────────────┘
```

### 1. 学习状态进度 (知识点级别)

**核心实现：** `LearningState` 状态机 + `LearningStateMachineImpl`

```
NOT_STARTED → LEARNING → MASTERED → PROFICIENT
                ↑            ↓
             FORGOTTEN ← REVIEWING
```

| 项目 | 说明 |
|------|------|
| 文件位置 | `education/domain/LearningState.java`, `education/service/impl/LearningStateMachineImpl.java` |
| 存储方式 | `ConcurrentHashMap<"studentId:knowledgeId", LearningState>` |
| 状态转换 | `startLearning()`, `passAssessment()`, `deepPractice()`, `forget()`, `scheduleReview()`, `giveUp()` |
| ⚠️ 问题 | **纯内存存储，重启丢失**。设计文档要求存入 RogueMap key `progress:{studentId}:{knowledgeId}`，但未实现 |

### 2. 能力值进度 (Bloom 六维度掌握度)

**核心实现：** `AbilityService` + `AbilityServiceImpl` + `AbilityValue`

| 维度 | 权重 | 说明 |
|------|------|------|
| 记忆 REMEMBER | 0.15 | 基础记忆 |
| 理解 UNDERSTAND | 0.20 | 概念理解 |
| 应用 APPLY | 0.25 | 实际运用 |
| 分析 ANALYZE | 0.20 | 分析推理 |
| 评价 EVALUATE | 0.10 | 批判评价 |
| 创造 CREATE | 0.10 | 创新创造 |

| 项目 | 说明 |
|------|------|
| 文件位置 | `education/ability/impl/AbilityServiceImpl.java`, `education/domain/AbilityValue.java` |
| 更新公式 | `updated = current + (100 - current) * accuracy * 0.1` (渐进式增长，上限 100) |
| 综合掌握度 | `overallMastery = Σ(dimension_score * weight)` |
| 持久化 | ✅ DB 表 `ability` (字段: remember, understand, apply, analyze, evaluate, create_score, overall_mastery) |
| 调用方 | `UpdateMasteryCmp` (workflow), `ScoreAnalysisNode` (agent graph), `AbilityQueryNode` (agent graph) |

### 3. 复习进度 (艾宾浩斯遗忘曲线)

**核心实现：** `EbbinghausCurve` + `ReviewScheduler` + `ReviewAgent` + `ReviewService`

| 项目 | 说明 |
|------|------|
| 文件位置 | `education/review/EbbinghausCurve.java`, `education/review/ReviewScheduler.java` |
| 复习间隔 | `{1, 3, 7, 15, 30, 90}` 天 (6 轮) |
| 遗忘公式 | `mastery = exp(-lambda * days)`，lambda 随复习轮次递减 |
| 持久化 | ✅ DB 表 `edu_review_task` (字段: review_date, review_round, status, result_score) |
| REST API | `GET /api/v1/review/today/{studentId}`, `PUT /api/v1/review/{id}/complete` |

**复习状态机：**

```
PENDING → IN_REVIEW → COMPLETED
              ↓
           FAILED → PENDING (重新安排)
PENDING → OVERDUE → PENDING (系统重置)
```

### 4. 学习计划进度

**核心实现：** `StudyPlanService` + `PlannerAgent`

| 项目 | 说明 |
|------|------|
| 文件位置 | `education/plan/impl/StudyPlanServiceImpl.java`, `agent/education/PlannerAgent.java` |
| 计划项状态 | `PENDING → IN_PROGRESS → COMPLETED / SKIPPED` |
| 持久化 | ✅ DB 表 `edu_study_plan` + `edu_study_plan_item` |
| ⚠️ 问题 | `PlannerAgent` 生成计划后，StudyPlanItem 的持久化尚未实现 (代码 line 74 有 TODO 注释) |

### 5. 索引重建进度 (系统任务级别)

**核心实现：** `IndexRebuildTask` + `RebuildStatus` + `KnowledgeSearchService.rebuildIndexWithProgress()`

| 项目 | 说明 |
|------|------|
| 文件位置 | `knowledge/task/IndexRebuildTask.java`, `knowledge/search/KnowledgeSearchService.java` |
| 执行方式 | `@Async` 异步执行，`Consumer<Integer>` 回调报告 0-100% 进度 |
| 重试机制 | 默认 3 次重试，可配置延迟 |
| 存储方式 | `ConcurrentHashMap<taskId, RebuildStatus>`，保留最近 100 个任务 |

### LiteFlow 工作流中的进度流转

```
learningChain (✅ 完整实现):
  checkKnowledgeCmp → loadResourceCmp → teacherCmp → practiceCmp → scoreCmp → updateMasteryCmp
                                                                                   ↓
                                                                    AbilityService.update() + ReviewScheduler.schedule()

reviewChain (⏳ 占位):
  loadReviewTaskCmp → generateReviewQuestionsCmp → reviewScoreCmp → updateReviewMasteryCmp

examChain (⏳ 占位):
  generateExamCmp → scoreExamCmp → analyzeExamCmp
```

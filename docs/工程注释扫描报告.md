# 工程注释扫描报告

## 扫描规则

- 扫描 `pom.xml`、`modules`、`tests`、`scripts`、`.github` 和 `docs` 中项目自有的 Java、Python、脚本、SQL、XML、YAML 文件。
- 跳过 `.git`、`target`、`node_modules`、`dist`、`build`、生成目录和历史备份。
- 每个 Java 接口都必须紧邻中文类型级 JavaDoc；方法参数、返回值和异常标签只保留必要的技术标识。
- 注释中的类名、包名、协议名、配置键、URL、Maven 坐标、路径和命令参数不翻译；自然语言说明统一使用中文。
- 禁止使用“中文接口说明：”或“中文说明：”等模板化前缀，注释应直接表达语义。

## 2026-09-12 基线

本次扫描覆盖后端项目全部自有源码和配置：接口类型缺失数为 0，英文自然语言注释命中数为 0，模板前缀命中数为 0。扫描器及夹具测试位于 `scripts/architecture/check_chinese_comments.py` 和 `scripts/architecture/tests/test_chinese_comments.py`。

中文注释扫描不再把“扫描通过”表述为语义审查完成。当前功能语义扫描发现生产历史问题 3939 条、测试观察项 307 条；基线策略只禁止新增已知模板问题，完整结果记录在 [`工程功能注释整改清单`](工程功能注释整改清单.md) 和 `scripts/architecture/functional-javadoc-baseline.json`。类型级注释、方法级注释、参数和返回值仍必须结合实现说明真实职责、条件和结果。

CI 会在架构测试阶段重新运行扫描器，并额外检查每个 Java 类型都存在类型级 Javadoc。新增接口或英文自然语言注释会直接阻断构建；功能注释扫描器使用基线阻断新增模板问题，并输出文件、行号、完整类型/方法和问题类别。静态规则不能证明注释与实现完全一致，复杂类型仍需人工审查。

### 功能注释语义扫描

`check_functional_javadocs.py` 检查类型、方法、构造方法以及 `@param`、`@return` 和 `@throws` 的描述，识别类型模板、方法模板、参数模板、返回值模板、只重复名称、空描述和需要人工复核的测试说明。生产源码参与门禁；测试源码单独统计，不阻断生产门禁。完整问题基线位于 `scripts/architecture/functional-javadoc-baseline.json`，整改清单位于 `工程功能注释整改清单.md`。

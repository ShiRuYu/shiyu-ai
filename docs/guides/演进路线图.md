## Phase 1：地基加固（P0）

### 1.1 统一 ExecutionContext ⭐ 最高优先级

**状态**：⚠️ **部分完成（演进方向：轻量 Execution 模型 + NodeInput/NodeOutput）**

**原问题**：所有模块通过 Map<String, Object> 传递参数，类型不安全、不可追踪。

**当前落地情况（2026-08-04）**：

- Agent 执行已建立统一的 **Execution** 执行实例模型（`execution/Execution.java`），包含 agentId/version/status/input/output/errorMessage/userId/sessionId/startTime/endTime/durationMs/nodeExecutions/lastCheckpointId
- 节点间数据传递通过 **NodeInput / NodeOutput**（`node/NodeInput.java`、`node/NodeOutput.java`、`node/NodeFields.java`）标准化
- **未完成**：未引入完整的 `ExecutionContext` 对象（traceId/requestId/cancellationToken/metadata 等字段仍未统一到单对象），各节点仍以输入输出对象传递

**后续建议**：可在 AgentRuntime 之上引入 `ExecutionContext`，统一 traceId 链路与取消令牌，但**不新增独立 runtime 模块**（见 1.2）。

---

### 1.2 Runtime 独立 + Executor SPI

**状态**：❌ **未按原方案执行（架构决策变更）**

**原方案**：抽取 `shiyu-ai-runtime` 新模块，引入 Executor SPI（AgentExecutor/WorkflowExecutor/ChatExecutor/ComfyExecutor/EducationExecutor）。

**实际决策（2026-08-04）**：

- **未创建** `shiyu-ai-runtime` 模块
- **移除 LiteFlow**：`shiyu-ai-agent/workflow`、`shiyu-ai-workflow` 全部删除，流程编排统一由 Agent 引擎（LangGraph4j）承担
- 执行逻辑收敛在 `shiyu-ai-agent`（AgentRuntime + AgentExecutor），不再拆多种 Executor
- 教育执行通过 **education 模块的 Agent/节点**（ExamAgent/PlannerAgent/ReportAgent/ReviewAgent + 6 个业务节点 Creator）注册进 Agent 引擎，实现"平台引擎 + 业务执行器"的插件式扩展

**结论**：原"多执行器"规划已被"Agent 引擎统一编排 + 业务节点插件化"取代，功能等价且更简洁。

---

### 1.3 Capability 抽象到 ModelAdapter

**状态**：⚠️ **未引入 Capability 接口，但职责边界已厘清**

**现状（2026-08-04）**：

- `ModelAdapter` 仍是 Chat 能力接口（getChatModel/getStreamingChatModel），未引入 Capability 体系
- 但 **Embedding 已独立**为 `embedding/EmbeddingService`（BGE-small-zh ONNX 本地嵌入），不依赖平台 Chat 能力
- ModelManager 负责多平台适配器生命周期与弹性包装

**后续建议**：若需支持 Vision/Audio/Reasoning 等异构能力，可再引入 Capability 抽象；当前 Chat + Embedding 分离已覆盖主要场景。

## Phase 2：能力增强（P1）

### 2.2 事件系统升级

**状态**：⚠️ **部分完成（事件体系已健全，异步化未统一）**

**当前事件体系（2026-08-04）**：

| 事件类 | 触发时机 | 状态 |
|--------|---------|:----:|
| AgentExecutionStartedEvent | Agent 开始执行 | ✅ |
| AgentExecutionCompletedEvent | Agent 执行完成 | ✅ |
| AgentExecutionFailedEvent | Agent 执行失败 | ✅ |
| NodeExecutionStartedEvent | 节点开始执行 | ✅ |
| NodeExecutionCompletedEvent | 节点执行完成 | ✅ |
| ModelCallEvent | 模型调用 | ✅ |
| AuditEvent | 审计日志 | ✅ |
| DomainEvent (基类) | 领域事件基类 | ✅ |

**缺口**：PromptBuilt/KnowledgeRetrieved/MemoryRetrieved/ToolCalling/ModelStreaming/TokenUsage 等细粒度事件未实现；Spring 事件广播仍为同步（未统一异步化）。

### 2.3 丰富 ExecutionStatus

**状态**：⚠️ **部分完成**

**当前状态枚举（2026-08-04）**：

```java
public enum ExecutionStatus {
    PENDING, RUNNING, PAUSED, COMPLETED, FAILED, CANCELLED
}
```

**对比原规划**（QUEUED / WAITING_TOOL / WAITING_MODEL / WAITING_USER / CANCELLING 未引入）。当前 6 状态 + 终态判定（isTerminal）已满足主流程；异步等待类场景（WAITING_*）待后续按需补充。

## Phase 3：细节打磨（P2）

### 3.1 拆分 DocumentIngestionService

**状态**：✅ **已完成（架构重构为 retrieval 体系）**

2026-08-04 知识平台重构后：

- 原 `rag/` 的 RagService/RagOrchestrator/LlmReranker/Reranker **已删除**
- 统一检索收敛为 **`retrieval/` 包**：`KnowledgeRetrievalService` + `EmbeddedKnowledgeRetrievalService`（向量 + 全文 + RRF 融合 + 引用）
- 文档摄入保留 `rag/DocumentIngestionService`（解析→分块→向量化）+ `task/EmbeddedIngestionWorker`（异步任务）
- 上传独立为 `upload/KnowledgeDocumentUploadHandler` + `KnowledgeDocumentUploadService`

---

### 3.2 统一 ExecutionResult

**状态**：⚠️ **部分完成**

- 执行输出仍以 Execution 实例（含 output Map + status + nodeExecutions）承载
- 未引入独立 `ExecutionResult` 类（含 toolCalls/cost/token/traceId/events 聚合）
- 用量统计由 `shiyu-ai-usage`（UsageCollector + UsageService）独立承担，不依赖 ExecutionResult

---

### 3.3 ExecutionLogger

**状态**：⚠️ **部分完成（以事件+审计+日志保留替代）**

- 结构化审计：`AuditService` / `AuditLogBO` / `AuditEventListener`（审计操作落库）
- 执行时间线：`TimelineService` / `ExecutionTimelineBO` / `TimelineEventListener`
- 日志保留：bootstrap `LogRetentionService`（日志保留策略）
- 可观测：`application-observability.yml` 独立 profile（OpenTelemetry + Micrometer + Prometheus）
- **未引入**专用 ExecutionLogger 类，运营统计职责由 usage + audit + observability 分担

---

### 3.4 教育节点完善

**状态**：✅ **已完成（且完成解耦）**

- 原规划中 AbilityQuery/EducationTeach 等"抛 UnsupportedOperationException"的节点，现已完整实现：
  - `AbilityQueryNode`（能力查询）、`TeachNode`（教学）、`PracticeNode`（出题）、`ScoreAnalysisNode`（评分）、`ReviewScheduleNode`（复习）、`PrereqCheckNode`（前置检查）
- 且这些节点已随教育 Agent **整体迁入 `shiyu-ai-education`**（agent/graph + agent/node/creator），平台节点与业务节点物理分离

## Phase 4：持续优化（P3）

### 4.1 泛型 BaseRepository

**状态**：⚠️ **部分演进（DDD 仓储接口化）**

### 4.3 教育节点完善

**状态**：✅ 已完成（同 3.4）

## 不推荐的行为

- ❌ 一次性重构所有模块（风险过高）
- ❌ 重新引入多 Executor Runtime 模块（已被 Agent 引擎统一编排取代，避免重复建设）
- ❌ 用设计模式硬套场景（适度抽象）
- ❌ 推翻现有代码重写（增量演进）

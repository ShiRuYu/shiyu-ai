## Phase 1：地基加固（P0，预计 3-4 周）

### 1.1 统一 ExecutionContext ⭐ 最高优先级

**问题**：当前所有模块通过 Map<String, Object> 传递参数，类型不安全、不可追踪。

**目标**：引入 ExecutionContext 取代各处散乱的 Map 传参。

**改动范围**：

| 文件 | 改动内容 |
|------|---------|
| shiyu-ai-core/context/ExecutionContext.java | 新增统一上下文类 |
| AgentRuntime.java | 改接口参数为 ExecutionContext |
| AgentRuntimeImpl.java | 适配新接口 |
| Graph.java | execute(input) → execute(ExecutionContext) |
| 所有 BaseNode.process() | 统一接收 ExecutionContext |
| Execution.java | 持有 ExecutionContext 引用 |
| Controller 层 | 移除参数拼装逻辑，委托给 Application |

**关键类定义**：

``java
public class ExecutionContext {

### 1.2 Runtime 独立 + Executor SPI

**问题**：AgentRuntime 在 agent 模块内部，Workflow/Chat/Education 各自实现自己的执行逻辑，重复建设。

**目标**：抽取 shiyu-ai-runtime 模块，引入 Executor SPI。

**新模块结构**：

`
shiyu-ai-runtime/
├── context/          ExecutionContext（引用 core）
├── pipeline/         PipelineStep 接口 + 默认实现
├── executor/
│   ├── Executor.java           (SPI 接口)
│   ├── ExecutorRegistry.java   (注册中心)
│   ├── AgentExecutor.java      (从 agent 移入)
│   ├── WorkflowExecutor.java   (从 agent 移入)
│   ├── ChatExecutor.java       (新建)
│   ├── ComfyExecutor.java      (扩展预留)
│   └── EducationExecutor.java  (扩展预留)
├── scheduler/        TaskScheduler （定时/延迟任务）
├── registry/         插件注册
├── state/            统一状态机
├── event/            统一事件（从 agent 提升）
├── metrics/          执行指标采集
├── cancellation/     取消令牌管理
├── checkpoint/       检查点通用化
├── retry/            重试策略通用化
├── streaming/        流式处理通用化
├── persistence/      执行持久化通用化
└── spi/              扩展点
`

**核心接口**：

``java
public interface ExecutionRuntime {
    ExecutionResult execute(ExecutionContext ctx);
    Flux<ExecutionResult> executeStream(ExecutionContext ctx);
    void pause(String executionId);
    ExecutionResult resume(String executionId);
    void cancel(String executionId);
    ExecutionStatus getStatus(String executionId);
}

public interface Executor {
    String executorType();
    ExecutionResult execute(ExecutionContext ctx);
    boolean supports(ExecutionContext ctx);
}

@Component
public class ExecutorRegistry {
    private final Map<String, Executor> executors = new ConcurrentHashMap<>();
    
    public void register(Executor executor) {
        executors.put(executor.executorType(), executor);
    }
    
    public Executor getExecutor(String type) {
        Executor executor = executors.get(type);
        if (executor == null) {
            throw new IllegalArgumentException("不支持的执行器: " + type);
        }
        return executor;
    }
    
    public List<String> getAvailableExecutorTypes() {
        return new ArrayList<>(executors.keySet());
    }
}
``

**迁移步骤**：

1. 新建 shiyu-ai-runtime Maven 模块
2. 从 shiyu-ai-agent 移入 AgentExecutor、CheckpointManager、EventPublisher 核心逻辑
3. 引入 ExecutorRegistry + Executable SPI
4. 在 shiyu-ai-agent 中注册 AgentExecutor
5. 在 shiyu-ai-education 中注册 EducationExecutor
6. 后续新增 executor 无需改 Runtime

### 1.3 Capability 抽象到 ModelAdapter

**问题**：ModelAdapter 假设所有平台都提供 Chat 能力，无法表达不同模型的能力差异。

**目标**：引入 Capability 接口体系。

**设计**：

``java
// 能力标记接口
public interface Capability { }

// 具体能力
public class ChatCapability implements Capability {
    ChatModel getChatModel();
    StreamingChatModel getStreamingChatModel();
}

public class EmbeddingCapability implements Capability {
    EmbeddingModel getEmbeddingModel();
}

public class ImageCapability implements Capability { ... }
public class VisionCapability implements Capability { ... }
public class AudioCapability implements Capability { ... }
public class ReasoningCapability implements Capability { ... }

// 新 ModelAdapter
public interface ModelAdapter {
    String getPlatformType();
    boolean isAvailable();
    
    // 能力查询
    <T extends Capability> T getCapability(Class<T> type);
    boolean hasCapability(Class<? extends Capability> type);
    
    // 能力列表
    List<Class<? extends Capability>> getSupportedCapabilities();
    
    // 缓存管理
    void clearCache();
}
``

**实现示例**：

``java
public class GenericPlatformAdapter implements ModelAdapter {
    private final Map<Class<? extends Capability>, Capability> capabilities = new HashMap<>();
    
    public GenericPlatformAdapter(String code, String baseUrl, String apiKey, String defaultModelName, 
                                   List<Class<? extends Capability>> supportedCapabilities) {
        // 注册支持的能力
        if (supportedCapabilities.contains(ChatCapability.class)) {
            capabilities.put(ChatCapability.class, new DefaultChatCapability(baseUrl, apiKey, defaultModelName));
        }
        if (supportedCapabilities.contains(EmbeddingCapability.class)) {
            capabilities.put(EmbeddingCapability.class, new DefaultEmbeddingCapability(baseUrl, apiKey));
        }
        // ...
    }
    
    @Override
    public <T extends Capability> T getCapability(Class<T> type) {
        Capability cap = capabilities.get(type);
        if (cap == null) {
            throw new UnsupportedOperationException("平台 " + code + " 不支持能力: " + type.getSimpleName());
        }
        return type.cast(cap);
    }
}
``

**使用示例**：

``java
// 旧代码
ChatModel model = modelManager.getChatModel("OPENAI", "gpt-4o");

// 新代码
if (modelManager.getAdapter("QWEN").hasCapability(VisionCapability.class)) {
    VisionCapability vision = modelManager.getAdapter("QWEN").getCapability(VisionCapability.class);
    // 处理视觉任务
} else {
    // 降级或报错
}
``

## Phase 2：能力增强（P1，预计 2-3 周）

### 2.1 Pipeline 编排层

**问题**：Prompt 构建分散在各 Node 内部，缺少统一的编排层。

**目标**：在 Runtime 中引入 PipelineStep，标准化 Prompt→Model 流程。

**设计**：

``java
public interface PipelineStep {
    String name();
    int order();               // 执行顺序
    void execute(PipelineContext context);
}

// 默认 Pipeline
@Bean
public PromptPipeline defaultPipeline(List<PipelineStep> steps) {
    return new PromptPipeline(steps.stream()
        .sorted(Comparator.comparingInt(PipelineStep::order))
        .collect(Collectors.toList()));
}

// 步骤示例
@Component
@Order(10)
public class SystemPromptStep implements PipelineStep {
    public String name() { return "system-prompt"; }
    public void execute(PipelineContext ctx) {
        ctx.appendSystemPrompt("你是一个有帮助的 AI 助手...");
    }
}

@Component
@Order(30)
public class MemoryStep implements PipelineStep {
    public void execute(PipelineContext ctx) {
        String history = memoryService.buildConversationHistory(
            ctx.getSessionId(), ctx.getConfig().getMaxHistoryMessages());
        ctx.appendMessages(history);
    }
}
``

### 2.3 丰富 ExecutionStatus

**问题**：当前只有 6 个状态，缺少中间状态。

**目标**：补充中间状态，支持精细化管理。

**新增状态**：

``java
public enum ExecutionStatus {
    PENDING,           // 等待执行
    QUEUED,            // 排队中（新增）
    RUNNING,           // 执行中
    WAITING_TOOL,      // 等待工具（新增）
    WAITING_MODEL,     // 等待模型（新增）
    WAITING_USER,      // 等待用户（新增）
    PAUSED,            // 已暂停
    CANCELLING,        // 取消中（新增）
    CANCELLED,         // 已取消
    FAILED,            // 失败
    COMPLETED;         // 完成
    
    // 状态机
    TRANSITIONS:
    PENDING        → {QUEUED, CANCELLED}
    QUEUED         → {RUNNING, CANCELLED}
    RUNNING        → {WAITING_TOOL, WAITING_MODEL, WAITING_USER, PAUSED, CANCELLING, COMPLETED, FAILED}
    WAITING_TOOL   → {RUNNING, WAITING_MODEL, PAUSED, CANCELLING, FAILED}
    WAITING_MODEL  → {RUNNING, WAITING_TOOL, WAITING_USER, PAUSED, CANCELLING, FAILED}
    WAITING_USER   → {RUNNING, PAUSED, CANCELLING, FAILED}
    PAUSED         → {RUNNING, CANCELLED}
    CANCELLING     → {CANCELLED}
    CANCELLED      → {}   (终态)
    FAILED         → {}   (终态)
    COMPLETED      → {}   (终态)
}
``

## Phase 4：持续优化（P3，持续进行）

### 4.1 泛型 BaseRepository

``java
public abstract class BaseRepository<T, K> {
    @Resource
    protected BaseMapper<T> mapper;
    
    public void insert(T entity) { mapper.insertSelective(entity); }
    public void update(T entity) { mapper.update(entity); }
    public void delete(K id) { mapper.deleteById(id); }
    public T selectById(K id) { return mapper.selectOneById(id); }
}
``

### 4.2 Controller 返回具体 VO

将所有返回 Map<String, Object> 的端点改为返回具体 VO 类，提高 API 类型安全和文档质量。

### 4.3 教育节点完善

## 依赖关系图

`
ExecutionContext ←──┐
                     ├── Runtime 独立
Capability 抽象 ─────┤
                     │
Pipeline ←───────────┤
事件升级 ←────────────┤
状态丰富 ←────────────┤
                     │
RAG 拆分 ────────────┤  (依赖 ExecutionContext)
Result 统一 ─────────┤  (依赖 Runtime)
ExecutionLogger ─────┘
`

**推荐执行顺序**：

1. **第 1 周**：ExecutionContext 设计 + 核心类实现
2. **第 2 周**：Capability 抽象 + ModelAdapter 改造
3. **第 3-4 周**：shiyu-ai-runtime 模块抽取 + ExecutorRegistry
4. **第 5 周**：Pipeline + 事件升级 + 状态丰富（并行）
5. **第 6-7 周**：RAG 拆分 + Result 统一 + Logger
6. **持续**：泛型 BaseRepo + VO 类型安全

---

## 不推荐的行为

- ❌ 一次性重构所有模块（风险过高）
- ❌ 先做 RAG 拆分再做 Runtime（依赖倒置）
- ❌ 用设计模式硬套场景（适度抽象）
- ❌ 推翻现有代码重写（增量演进）

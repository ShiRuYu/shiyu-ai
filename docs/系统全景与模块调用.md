# ShiYu 系统全景与模块调用

> 本文只保留跨模块关系和主要调用路径；逐条接口、字段和权限以生成参考文档为准。

## 1. 系统边界

```text
浏览器 / 其他客户端
        ↓ REST、SSE、OpenAPI
应用壳与认证适配
        ↓ contract / 事件
领域 implementation
        ↓
领域表、文件、向量索引和可选外部 provider
```

- `shiyu-ai-bootstrap`：完整业务包的启动、配置、provider 校验和数据库初始化。
- `shiyu-application`：应用装配和跨域只读组合，不承担领域规则。
- `shiyu-ai-web` 与 `infrastructure/*`：过滤器、异常、Web、MyBatis、存储、线程和向量适配。

后端只运行一个 `shiyu-ai-bootstrap`。平台能力始终装配；教育、课程、企业等业务实现通过
`shiyu.modules.<module-id>.enabled` 在同一进程内按需启用，不再复制 application 或根包扫描。

## 2. 后端模块关系

| 分组 | 规则 |
| --- | --- |
| `domains/*` | 平台领域拆为 `contract` 与 `implementation`；领域实现拥有服务、Repository、Mapper 和 SQL。 |
| `business/education` | 教育业务独立拆分，通过 Agent、Knowledge、Conversation 等 contract 协作。 |
| `shared` | 只放强类型 ID、`ActorContext`、事件、分页和公共错误。 |
| `infrastructure` | 只放技术能力，不新增业务决策。 |

依赖方向为：应用壳 → 领域 implementation → 领域 contract / Shared Kernel。领域 implementation 之间禁止直接依赖、跨域访问 Repository/Mapper 或跨领域 SQL JOIN。

## 3. 领域与数据归属

| 领域 | 主要能力 | 数据前缀 |
| --- | --- | --- |
| IAM | 登录、用户、租户、角色、菜单和权限 | `AUTH_*` |
| Agent / Conversation | Agent 图、执行、消息和生成运行 | `AGENT_*`、`CONVERSATION_*` |
| Model | 平台、模型和路由 | `MODEL_AI_*` |
| Knowledge / Memory | 知识、关系、索引和 MAGMA 记忆 | `KNOWLEDGE_*`、`VECTOR_*`、`MEMORY_*` |
| Governance | 用量、配额、审计和实时推送 | `GOVERNANCE_*`、`OBSERVATION_*` |
| Education | 课程、题库、考试和学习过程 | `EDU_*` |
| 技术支持 | 文件、上传、公共字典和基线记录 | `STORAGE_*`、`COMMON_*` |

每个领域维护自己的 H2 baseline。跨领域数据通过 contract 查询或事件传递；不共享领域表的 Repository。

## 4. 基础设施 provider

| 能力 | 默认 | 可选 |
| --- | --- | --- |
| 数据库 | H2 | MySQL、PostgreSQL |
| 文件 | local | S3、MinIO |
| 向量 | JVector | InMemory、pgvector |
| Redis 状态 | disabled | Redis |
| 事件 | in-process | PostgreSQL outbox、Kafka |

配置键统一使用 `shiyu.infrastructure.*.provider`。旧配置仅作兼容别名；切换前必须完成数据迁移、校验和回滚演练。

## 5. 请求与租户链路

```text
Bearer Token
  → Sa-Token / UserContextInterceptor
  → ActorContext + TenantScope
  → Controller 权限校验
  → Application / Domain Service
  → Repository（Flex 自动过滤 + 显式归属校验）
  → Result<T>
```

普通请求缺少租户作用域即拒绝；跨租户操作必须先授权，再在目标作用域内执行并恢复原作用域。JDBC、文件和向量索引使用同一可信租户来源，不把 `null` 或 `0` 当作放行值。

## 6. 主要业务旅程

| 旅程 | 调用摘要 |
| --- | --- |
| 登录 → 首页 | IAM 登录 → 获取租户/角色/菜单 → 前端按权限加载 Feature。 |
| 创建 Agent → 执行 | 创建定义和版本 → 校验并发布 → Runtime 生成 `AiRun` → SSE/普通响应。 |
| Conversation → Model | 保存消息和 `GenerationRun` → 通过 Model contract 路由 → Governance 记录用量。 |
| Knowledge → Retrieval | 上传文件 → 解析分块 → Embedding/索引 → 按租户空间检索并返回来源。 |

教育模块通过同样的认证、租户和基础设施边界提供 `/api/education/**`，不改变平台能力的 URL 或 Bean 名称。

## 7. 安全与事实来源

- 权限失败返回稳定业务码和 `401/403`；错误响应不得泄露堆栈或 SQL。
- 领域表由所属 implementation 维护，数据库基线归属由架构脚本检查。
- 接口路径和 schema 以 OpenAPI 快照及 [API接口参考](参考/API接口参考.md) 为准。
- 表、菜单和权限以 [领域模型与数据字典](参考/领域模型与数据字典.md)、权限矩阵和源码 seed 为准。
- 运行、测试和变更门禁见 [开发规范与对话决策](开发规范与对话决策.md) 与 [质量与联调报告](质量与联调报告.md)。

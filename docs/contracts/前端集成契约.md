# 前端集成契约

> 更新：2026-08-10
> 对应前端：`ShiRuYu/shiyu-ui` 的 `apps/web-naive`

## 1. API 基础约定

- 前端生产环境使用同源 `/api`，网关移除或保留前缀由部署配置统一决定。
- 普通响应使用 `Result<T>`：成功码 `200`，业务数据位于 `data`。
- 认证使用 `Authorization: Bearer <token>`。
- 分页参数必须以 Controller 声明为准；Agent 分页为 `pageNo`、`pageSize`。
- 菜单、权限码和用户上下文切换后必须视为一个新权限上下文，前端会丢弃旧动态路由并重新请求。

## 2. 动态菜单

`GET /menu/all` 返回树形 `RouteMenuVO[]`。字段、授权祖先规则与基线迁移见 [菜单信息架构](../architecture/菜单信息架构.md)。

前端在注册路由前会校验：

1. 返回值必须是数组；
2. `name`、`path` 必须非空，`name` 在整棵树中唯一；
3. `children` 必须是数组；
4. 非布局 `component` 必须映射到前端真实 `views/**/*.vue` 文件。

任一条件失败都会进入“菜单加载失败”页面。修改菜单基线时，后端提交必须同时给出迁移和 `DatabaseInitializerTest` 断言；前端提交必须同步组件注册或路由契约测试。

## 3. Chat SSE

### 请求

```http
POST /chat/send-stream
Accept: text/event-stream
Content-Type: application/json
Authorization: Bearer <token>

{"platform":"SILICON_FLOW","model":"optional","prompt":"hello"}
```

### 响应

Content-Type 必须为 `text/event-stream`。每个事件的 `data:` 是一个完整 `ChatResponse` JSON；不能依赖 TCP chunk 边界。

```text
data: {"success":true,"content":"你","platform":"…","model":"…"}

data: {"success":true,"content":"好","platform":"…","model":"…"}

```

前端按 SSE 空行拆帧，支持跨网络 chunk 的事件、多行 `data:`、`[DONE]` 和主动取消。服务端应在客户端断开时取消上游订阅，避免继续消耗模型 Token。

`ChatDemoControllerTest` 固化此端点的 SSE media type 和内容透传。

## 4. 质量门禁

仓库 `.github/workflows/ci.yml` 使用 Java 21 执行：

```bash
mvn --batch-mode --no-transfer-progress test
```

本地针对接口层可运行：

```bash
mvn -pl infrastructure/shiyu-ai-web -am \
  -Dtest=ChatDemoControllerTest \
  -Dsurefire.failIfNoSpecifiedTests=false test
```

发布前还需与前端 Playwright 关键路径回归一起通过。

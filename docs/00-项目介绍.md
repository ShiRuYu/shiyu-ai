# Shiyu AI Education Platform - 项目介绍

## 1. 项目背景

Shiyu AI Platform 是一个以 AI 能力为核心的智能平台，覆盖聊天、Agent、RAG、知识图谱、MCP、Workflow 等能力。

教育（K12）是该平台的首个业务域，目标构建一个覆盖 **幼儿园(K0) -> 小学 -> 初中 -> 高中 -> 高考** 的完整知识点学习系统。

系统不是简单的题库，而是采用 **知识图谱（Knowledge Graph）+ 学习路径（Learning Path）+ 能力模型（Competency Model）+ AI Agent** 的架构，设计为一个"教育知识操作系统（Education Knowledge OS）"。

## 2. 项目目标

| 目标             | 描述                                                                 |
| ---------------- | -------------------------------------------------------------------- |
| 知识点全覆盖     | K12 全学段、全学科、多教材版本知识点体系                             |
| 知识图谱         | 构建 DAG 知识点关系图，支持前置/后置/相似/关联关系                   |
| 智能学习路径     | 基于知识图谱 + 能力评估，自动规划个性化学习路线                      |
| AI Tutor         | 多 Agent 协作：讲解、出题、考试、复习、规划、分析                    |
| 能力模型         | Bloom Taxonomy 六维度（记忆/理解/应用/分析/评价/创造）能力跟踪       |
| 艾宾浩斯复习     | 基于遗忘曲线自动生成复习计划（1/3/7/15/30/90 天）                   |
| 轻量化部署       | 单 Jar 部署，无需 Redis/Neo4j/ES/Milvus/Kafka 等外部中间件           |
| 平台化扩展       | 教育只是 AI Platform 的一个业务域，未来可扩展办公、生活、企业知识库  |

## 4. 技术选型决策

### 4.1 为什么不用 Redis

- 知识点数量约 15000，关系边约 10~20 万，缓存数据量不大
- RogueMap 嵌入式 KV 即可满足：O(1) 查询 + LRU + TTL + 持久化
- 减少部署依赖，单 Jar 运行
- 如需扩展，RogueMap 可替换为 Redis，接口层不变

### 4.2 为什么不用 Neo4j

- K12 知识点总量约 15000 个，关系边约 10~20 万
- RogueMap 存储图结构 `Map<Long, Node>` + O(1) 查询，完全胜任
- DFS/BFS/拓扑排序等算法在内存图上执行即可
- 接口层定义 `GraphStore`，未来可无缝替换为 Neo4j

### 4.3 为什么不用 Elasticsearch

- 知识点 15000 + 课程 5000 + 题目 100 万，规模可控
- Trie + 倒排索引 + BM25 放在 RogueMap 中实现全文检索
- 避免引入独立搜索引擎，降低运维成本
- 题目达到千万级时可引入 Lucene

### 4.4 为什么不用 Milvus / Qdrant / PGVector

- RogueMap Embedding 模块直接存储 float[] 向量
- 支持 TopK 相似度查询
- 无需独立向量数据库

### 4.5 为什么采用 Spring AI

- 统一抽象 Layer，屏蔽不同 LLM Provider 差异
- 原生支持 SSE/Streaming
- 与 Spring Boot 生态无缝集成

### 4.6 为什么采用 LiteFlow

- 声明式流程编排，避免 if-else
- 学习流程（检查->讲解->练习->评分->更新）天然适合 Chain 模式
- 热更新流程，无需重启
- 组件化，每个步骤独立可测试

### 4.7 为什么采用 LangGraph4j

- 复杂 Agent 场景需要状态机图
- Planner -> Knowledge Search -> Teacher -> Practice -> Review 是典型图执行
- 支持 State 传递和条件分支
- 支持 Streaming 输出

### 4.8 为什么采用 MCP

- AI 工具扩展标准化协议
- 教育场景需要 OCR / TTS / ASR / 出题 / 生成 PPT 等工具
- MCP 让 LLM 可以调用外部能力
- 与 Spring AI 集成良好

## 5. 为什么采用 RogueMap

RogueMap 是嵌入式堆外 KV + 持久化 + Embedding 模块，在本系统中承担以下职责：

| 职责           | RoguMap Key 示例            | 说明                         |
| -------------- | --------------------------- | ---------------------------- |
| 知识图谱       | `graph:1001`                | 节点 + 邻接表                |
| Embedding      | `vector:1001`               | 浮点向量                     |
| AI Memory      | `memory:user:1`             | 对话历史 + 摘要              |
| 缓存           | `cache:course:100`          | LRU + TTL                    |
| 全文索引       | `search:term:二次`          | 倒排索引 posting list        |
| 推荐索引       | `recommend:user:1`          | 用户偏好向量                 |
| 学习状态       | `progress:user:1:know:200`  | 掌握度 + 复习时间 (待实现持久化) |

优势：

- 嵌入式，无网络开销
- 堆外内存，GC 友好
- 持久化，启动无需预热
- O(1) 查询
- 统一数据接口，可替换为外部实现

## 6. 项目定位演进

```
Shiyu AI Platform
       +
AI Agent Platform
       +
Education OS
       +
Knowledge Engine
```

最终目标是一个 **AI 平台**，支持：

- 聊天（Chat）
- Agent（多智能体）
- RAG（检索增强生成）
- 知识图谱
- 教育（K12）
- 办公
- MCP（工具扩展）
- Workflow（工作流）

**教育只是其中一个插件。**
